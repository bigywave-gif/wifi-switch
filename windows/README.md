# WiFi Switch · Windows

每个版本的新增、修复、调整和验证限制见 [完整版本记录](CHANGELOG.md)。本次仅补录文档，不修改既有安装包。

**Windows 10/11，Intel/AMD 64 位（x64）。** 独立 Windows 原生程序，不依赖 Mac 版本。
此版本处于内部验收阶段：交叉编译和逻辑测试不等于 Windows 实机安装及真实 Wi-Fi 认证通过。

## 安装

运行 `WiFi-Switch-0.1.10-windows-x64-setup.exe`，按安装向导完成安装。
安装向导提供“选择安装位置”步骤：默认目录为 `%LOCALAPPDATA%\Programs\WiFi Switch`，
可直接使用，也可点击“浏览”选择其他当前用户有写入权限的目录。升级时默认填入上次安装目录。
程序安装后出现在开始菜单的 **WiFi Switch** 文件夹中。
已安装应用列表提供卸载入口。不需要手动复制 EXE，也不需要另外安装 .NET。
不要使用“以管理员身份运行”启动本应用：Wi-Fi 配置按登录会话隔离，管理员会话保存的网络配置
对普通会话不可见，容易导致连接被系统取消或当前账号无法识别。以管理员身份运行时应用会明确警告。

升级前从托盘齿轮菜单选择“退出系统”。安装向导检测到应用运行时会要求先退出。
安装结束不会自动连接网络，默认也不会自动启动应用。可在完成页勾选启动。
安装包尚未进行 Authenticode 商业代码签名；Windows 可能显示未知发布者提示。
仅从可信内部渠道取得安装包；设备受管理策略限制时联系管理员，不关闭系统安全保护。

## 使用

1. 从开始菜单打开应用。顶部状态栏左侧显示连接状态、Wi-Fi 和当前账号，右侧显示账号总数。
   仅一块 Wi-Fi 网卡时自动选择；多块网卡时在状态栏下方的独立区域选择，不占用账号总数的位置。
2. 点击 **添加账号**。备注选填，列表只显示备注、不展示登录用户名。
3. 点击 **扫描附近 Wi-Fi**，在可滚动列表中勾选一个或多个网络，也可以手动添加 SSID。
   企业 Wi-Fi、普通密码 Wi-Fi、手机热点和开放网络均可选择。
   隐藏网络需通过“设置”勾选隐藏网络并指定实际认证方式。
4. 必填项随选择自动变化：含企业网络需要用户名和密码；普通密码网络只需密码；
   仅开放网络均可留空；未选网络或类型未识别时可留空用户名，但需密码。
   保存按钮旁会说明未填写或暂时无法保存的原因。
5. 展开账号，点击所需 Wi-Fi 右侧的 **连接**。只有该账号的目标 Wi-Fi 显示“连接中…”，
   其他连接按钮保持“连接”；连接期间暂不可重复发起请求。主窗口与托盘面板一致。切换时会短暂断网。
6. 账号更多菜单支持修改和删除。编辑密码留空保留原密码；眼睛按钮可查看保存的密码，
   关闭明文显示后可输入新密码。窗口失去焦点时隐藏密码。
7. Wi-Fi 更多菜单提供 **重新连接** 和 **移除 Wi-Fi**。移除只解除关联，不主动断开系统连接。
8. 关闭主窗口后应用继续运行。点击通知区域的双向箭头图标打开紧凑面板；
   账号默认收起，管理窗口默认展开。齿轮菜单提供 **配置管理** 和 **退出系统**。

密码不同的网络应分别建立账号。同一账号关联多个 Wi-Fi 时共享同一份凭据。
关联是应用内保存的配置关系，不会同时连接多个 Wi-Fi。点击“连接”只处理所选账号下的目标网络，
同一网卡由原连接切换至目标连接。不同账号可以关联同一个 Wi-Fi，不按用户名跨账号禁止保存。
修改当前账号用户名或密码并保存，会用新凭据重新连接当前 Wi-Fi；只改备注、关联或其他账号不会切换。
保存后认证失败会保留新信息并明确显示错误。

## 连接状态与自动恢复

- 同一个 Wi-Fi 共用以真实 SSID 命名的 Windows WLAN 配置，例如 `Example-Enterprise`。
  不再按账号创建 `WiFiSwitch-编号` 网络条目。多个账号仍分别保存在应用中，连接时将所选凭据交给同一网络配置。
  新建的配置默认为**所有用户**范围，与 Windows Wi-Fi 菜单行为一致；已有同名配置保留其原有
  所有用户/当前用户范围及企业证书信任要求，不另建同名的用户配置副本。
  发起连接时，应用将目标配置切换为自动加入并提升到最高优先级（与 Windows Wi-Fi 菜单
  勾选“自动连接”等效）。这是为了防止断开旧会话的瞬间，Windows 自动配置服务把网卡
  抢给另一个自动加入的网络，导致刚建立的连接被取消（实测 0x38001）。因此即使本次连接失败，
  该网络保持自动加入与最高优先级；连接失败本身仍按失败显示，不会自动重试提交凭据。
  绿色标记需要匹配网卡、SSID、配置中的内部账号标记及可用 IP，并且本次连接没有失败。
  配置、自动加入、凭据和账号标记在发起连接前准备完成；认证完成后不再改写目标配置或凭据，
  保留 Windows 本次认证中确认的证书信任信息。账号标记只记录本次提交的凭据归属，
  不代表认证成功；还必须收到本次连接成功通知，并连续确认账号、配置与可用 IP 才显示成功。
  该内部标记是账号 UUID，不出现在网络名称中，也不含用户名密码。
  连接成功后保留此配置的系统自动加入设置；权限或策略阻止自动加入设置时明确提示。
- 当前正常账号置顶，绿色圆圈黑色对钩与连接按钮对齐。正常 Wi-Fi 行显示绿色状态点；
  异常显示红点，可点击查看错误和手动重新连接。用户名密码认证失败时提供修改账号入口，不自动弹出编辑框。
- 账号记录保存在用户目录，更新、退出重开、休眠和系统重启不清空。
  如果系统当前配置没有匹配的内部账号标记，即使 SSID 相同，也显示“当前账号未识别”，保留历史记录。
  标记表示应用上次提交的账号凭据，配合成功通知和连接状态确认，不是对认证服务器身份的实时查询；系统外部独立改动凭据可能无法被识别。
- 每 5 秒检查状态。异常时先等待 10 秒让系统恢复；仍异常才恢复原账号。
  网络故障最多失败 3 次，之后需手动重连；系统明确返回认证拒绝、密钥不匹配或缺少凭据时立即停止。
  停止状态跨应用重启保留。若停止后 Windows 自行恢复了同一账号的连接（标记匹配且有 IP），
  应用清除该次连接的失败记录和错误提示并更新为正常，不会再次自动重试；其他操作错误不会被清除。
  证书错误也可能导致认证失败，不把所有错误都说成密码错误。
- 不主动打开已关闭的 Wi-Fi；休眠、缺少权限、网卡不可用或系统已连接其他账号/网络时不抢占连接。
  不删除系统网络、不关闭网卡、不绕过证书验证。
  三次限制只针对本工具的重试，不限制 Windows WLAN 服务自身的自动加入。
- 状态检测范围是 WLAN 连接及 IP 地址，不保证互联网或公司业务可用，也不会自动处理网页 Portal。

### 认领当前连接（0.1.6）

系统已连接账号关联的 Wi-Fi 并取得 IP，但应用无法确认是记录中的账号时（例如连接来自
Windows Wi-Fi 菜单，或账号标记丢失），主窗口显示“认领当前连接”按钮。确认是本人连接后点击，
应用把账号标记写入当前系统配置并清除失败记录，恢复绿色状态。SSID 本身永远不足以认定账号，
认领必须由用户显式确认。配置属于其他登录会话（例如曾以管理员身份运行）或当前用户无权写入时，
认领会明确失败并说明原因，不静默改写。
认领写入后最多等待 5 秒，连续确认账号标记和可用 IP；期间防止重复认领或连接。
如果系统稍后才恢复，认领的状态校验提示会在下一次轮询确认同一账号、网卡、配置和 IP 后自动清除，
不要求重新连接，也不依赖是否存在连接失败记录。权限、保存或其他操作错误不会因此被清除。

### 连接被取消或切换后断网

切换到不同 Wi-Fi 配置时，由 Windows 的连接接口处理旧连接。
同一 Wi-Fi 切换账号时共用系统配置，先查询网卡状态并连续确认已断开，再更新凭据并重新认证；
不能把旧会话仍然在线当作新账号连接成功。修改权限与公司策略限制在断网前检查。
新连接仅接收对应网卡、配置且已收到“开始连接”通知后的结果，避免把较早的取消通知当成本次结果。

`0x38001` 表示 Windows 取消了连接操作，不等同于密码错误。
如果手动连接失败、原先有可用网络、原配置与目标配置不同且网卡仍处于断开状态，
应用会尝试一次用原 Windows 配置恢复网络；不会重试失败目标的密码，也不会覆盖已被用户切换的网络。
恢复成功仍显示目标账号连接失败，不把它标为当前账号。原配置无法恢复时，请从系统 Wi-Fi 菜单手动连接。
修改同一配置的凭据后不能保证恢复旧凭据。

### 0.1.7 信任重复确认与残留错误修正

- 修复首次创建网络配置后，认证成功分支再次写回连接前的配置及 EAP 凭据的问题。
  自动加入已在连接前设置，成功后不应再次覆盖 Windows 在认证期间更新的信任状态。
- 账号标记也改为在发起连接前准备，同一标记不重复写入；取得 IP 后只读取连接状态，
  避免因成功收尾时修改目标配置导致再次断开和认证。仍要求本次成功通知及三次连续健康采样。
- 配置或优先级准备失败时立即停止，不再忽略错误后继续使用可能过期的配置。
- Windows 稍后恢复同一账号连接时，同步清除该次连接错误文字、红色错误状态和修改账号提示；
  同 SSID 的其他账号、没有 IP、不可读状态以及其他操作错误均不会被误清除。

首次服务器证书信任确认仍由 Windows 完成，证书校验保持启用。本次修复消除应用在成功收尾阶段
触发的重复写入，不保证所有企业策略或证书变化场景都只提示一次。详见 `docs/verification-0.1.7.md`；
本机交叉编译及逻辑测试已完成，真实信任弹窗和企业 Wi-Fi 连接仍待 Windows 实机复测。

### 0.1.6 会话隔离、认证超时与死锁状态修正（历史，标记时序已由 0.1.7 替代）

实测发现同一账号连续失败而系统却能连上同一网络的组合，来源有四处：

- 新建的 WLAN 配置原先按当前用户保存。以管理员身份运行时写入的配置对普通会话不可见，
  反之亦然，导致每次连接都认为配置不存在而重写，且连接完成后立即被 Windows 取消。
  现在新建配置默认所有用户范围；应用启动时检测到管理员令牌会显示警告并建议正常启动。
- 认证等待原先 45 秒超时并主动断开仍在进行的认证。实测 PEAP 认证有超过 45 秒才完成的路径。
  现在等待 90 秒，且 Windows 报告 802.1X 认证仍在进行时超时不再打断，只说明系统可能稍后自行完成。
- 失败 3 次停止后，即使系统随后自行恢复同一账号的连接，失败记录也不会清除。
  现在检测到标记匹配且有 IP 的健康连接即恢复正常显示（不触发重试）；
  标记不匹配时提供“认领当前连接”入口，由用户确认后写入账号标记并清除失败记录。
- 应用保存的配置原为手动加入且优先级最低。断开旧会话后，Windows 自动配置服务会把网卡
  抢给优先级更高的其他自动加入网络（实测为 0.5 秒内连接成功后立即被 0x38001 取消，
  新会话一并被拆除）。现在发起连接时先把目标配置设为自动加入并提升到最高优先级，
  再执行断开与连接；诊断日志以不可逆哈希记录各事件的配置名，便于识别竞争来源。
- 认证成功后立即写入的账号识别标记会使 Windows 重置该配置并取消刚建立的连接
  （实机四次认证成功均在写入后约 0.5 秒被 0x38001 拆除，哈希证实拆的就是本配置）。
  现在标记改为在连接确认稳定（配置匹配且有 IP）之后写入；确认阶段按网卡、SSID、
  配置名与 IP 判定，不依赖尚未写入的标记。

此修正已通过自动测试与 Windows x64 编译，真实企业认证及管理员/普通会话切换仍需实机验证。

### 0.1.5 企业认证流程修正

- 已有企业配置适合显式账号认证时，直接保留原配置，只提交本次账号的 EAP 凭据后连接，
  不再在每次连接前后重复调用 `WlanSetProfile`。保留原来的自动/手动加入、证书和服务器验证设置。
- 若原配置使用 Windows 登录账号或快速认证缓存，仍需调整相关认证选项，避免沿用上一个账号；
  启用单点登录的配置在断网前明确停止，不静默移除公司配置的单点登录。
- 认证完成后才写入账号关联标记，仍须通过 IP 与账号关联验证才能显示成功。
- 超时取消后查询真实网卡状态，即使没有收到“断开完成”通知也能确认断开；
  状态不可读、认证中或已经连接到网络时，不误报已断开。
- 诊断会记录 `profile plan ... writeRequired=False`、`profile preserved without WlanSetProfile`
  以及 `disconnect confirmation=True/False`，用于区分配置保留与取消确认的实际执行结果。

此修正已通过自动测试与 Windows x64 编译，但仍需在目标 Windows 电脑验证真实企业认证。
原日志仅能证明认证等待后由应用取消，不能据此断定凭据格式错误或管理员权限不足。

### 旧版额外网络条目清理

打开 0.1.2 或更新版本后，自动清理未在使用的旧版 `WiFiSwitch-编号` 配置：
只处理当前用户范围、名称与旧版 UUID/SSID 哈希规则完全匹配的条目，
不删除正常命名的系统网络或公司策略配置，不删除应用中的账号、关联或密码。
正在连接、已连接或状态无法确认的旧条目会暂时保留，界面给出说明。
通过本应用重新连接真实名称的配置成功后再次清理；不会为了清理旧条目主动断开现有连接。
旧版本保存的当前账号与失败记录继续读取，在下一次连接成功时更新为新配置记录。

### 连接诊断（0.1.4）

连接失败、超时或一直等待时，点击主窗口底部的 **导出诊断**，或托盘齿轮菜单 → **导出诊断**。
异常详情窗口也可以导出。选择保存位置后，把生成的 ZIP 提供给排查人员。
连接仍在进行时也能导出，不必等到超时。演示模式不采集真实日志。

日志从读取凭据之前开始，依次记录网卡状态、扫描、配置检查、旧会话结束、配置写入、
EAP 凭据提交、Windows 关联/认证通知、IP 检查、自动加入设置和最终状态保存。
每次连接都有独立编号、带时区时间、累计耗时、阶段开始和结束耗时。
等待 Windows 返回结果时每 5 秒记录一次状态，帮助区分发现网络、关联接入点、认证和获取 IP。
日志记录原始 API 返回码、WLAN 原因码、802.1X 状态及可用的 EAP 错误码。
证书过期、凭据拒绝等已知 EAP 错误附有分类；未知错误保留原始值，不推断成密码错误。

- 最近记录：`%LOCALAPPDATA%\WiFiSwitch\last-connection.log`。
- 历史记录：同目录 `diagnostics`，保留最近最多 10 次连接，每次最多 1500 行末尾记录，超出时注明截断数量。
- 后台每秒保存新增日志，不再只在连接结束后保存。磁盘写入失败不会改变连接结果，当前内存日志仍可导出。
- ZIP 只含应用诊断日志与说明，不包含 `accounts.json`、密码、用户名、账号备注、SSID、IP/MAC 地址、
  完整配置 XML 或原始认证载荷。日志可记录凭据是否存在以及是否带域前缀，不记录具体值。
- API 返回 0 不等于认证成功。只有 `END success=True` 表示应用完成连接验证和状态保存；
  中途退出的记录会保留 `active=True` 及最后阶段。

等待连接结果最长 90 秒。超时后，只有确认仍为本次目标配置且仍在连接才请求断开并等待完成；
802.1X 认证仍在进行（Windows 报告认证中且无失败原因）时不打断连接，
因为较慢的 RADIUS 路径可能在等待期之后才完成；已连接成功、其他网络或状态不明时也不强制断开，
并明确说明未确认结果。
如果扩展通知不可用，依次回退到 ACM + ONEX、基本 ACM 通知并记录注册错误，不阻止应用启动。
诊断记录能缩小失败范围，但 Windows 没有返回具体原因时，仍可能需要系统或认证服务器日志。
此版本增强诊断，不代表所有企业认证问题均已解决。

## 企业 Wi-Fi 与系统权限

企业认证适配 PEAP/MSCHAPv2 用户名密码方式。复用同名的 Windows 企业网络配置，
保留证书信任及服务器限制，连接时更新所选账号的认证数据。
同名配置指向其他 SSID、由公司策略管理或当前用户无修改权限时，在主动断网前停止并说明原因。
不存在已有配置时使用启用服务器证书校验的 PEAP 配置。此时 Windows 可能弹出
“继续连接？”的服务器证书确认框：请在网络浮窗中点击“连接”确认一次，认证才会继续；
应用等待期间会提示这一点。确认一次后通常不再重复弹出。若需彻底免确认，
请向 IT 获取 RADIUS 服务器名及根证书 SHA-1 指纹，在关联 Wi-Fi 的“设置”中填写。
EAP-TLS 客户端证书、第三方 EAP、企业策略限制或 Credential Guard 不兼容场景，应由管理员配置，
不通过关闭安全功能解决。首次连接可能仍需要 Windows 完成证书或权限交互。

较新的 Windows 版本要求位置访问权限才能扫描 Wi-Fi 或读取当前网络信息。
若提示拒绝访问，请在 **Windows 设置 → 隐私和安全性 → 位置** 中检查桌面应用权限。
这是 Windows 对附近 Wi-Fi 信息的隐私限制；本应用不采集地理坐标。管理员权限不等于位置授权。
其他 WLAN 操作的访问拒绝也可能来自用户权限或企业策略，不能统一解释为缺少位置权限。
无线服务不可用时请确认 WLAN AutoConfig 服务正常，再重开应用。

## 数据及卸载

- 账号备注、用户名、关联和连接记录：`%LOCALAPPDATA%\WiFiSwitch\accounts.json`。
  密码不写入 JSON、日志或命令行；替换配置时保留 `.backup` 文件，文件损坏时停止写入。
- 密码：当前 Windows 用户的凭据管理器，条目名 `WiFiSwitch/Accounts/<账号 UUID>`。
  通过系统接口直接保存和读取，不要求每次手输。
- Windows WLAN 服务还会保存连接配置及其认证数据，这是系统 Wi-Fi 自动连接所需的独立数据。
  删除本工具账号会删除本工具凭据，但不自动删除 Windows WLAN 配置或中断当前连接；
  若需彻底清除系统缓存，请在 Windows 设置中管理已知网络。
- 正常卸载保留账号、密码及系统网络配置，便于重装；新用户首次安装为空。
  自定义程序安装目录不改变账号和密码的保存位置。若要更换已有程序的安装目录，
  建议先正常卸载再安装到新目录，避免保留旧程序副本；账号数据会保留。
  不导入 Mac 账号数据，不与 iCloud 钥匙串同步，不修改 Mac 的任何代码或配置。
- 同一登录会话只允许一个实例，防止多个版本并发覆盖账号记录。

## 从源码构建

需要 .NET 10 SDK 和 NSIS 3；macOS 的打包校验另外使用 7-Zip 独立解包。图标资源已包含在源码中。在 `windows/` 内执行：

```powershell
.\scripts\build.ps1
```

macOS 交叉编译可执行 `bash windows/scripts/build.sh`，仅操作 `windows/`。
安装包位于 `windows/dist/`；独立测试使用 `dotnet run --project windows/tests/WiFiSwitch.Tests`。
`WiFiSwitch.exe --demo` 使用内存示例和模拟网络，不读写真实账号或密码。
在将来的 Windows 测试机上可执行 `scripts/smoke-test.ps1`，使用随机测试条目检查真实凭据管理器的
新增、读取、更新、删除，以及配置持久化；结束后清理测试数据，不执行任何 Wi-Fi 操作。
