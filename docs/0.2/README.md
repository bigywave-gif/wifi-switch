# WiFi Switch 0.2 产品设计方案

状态：交互方案与 Demo。基线：`macos-v0.1.68`。本分支不代表 0.2 功能已接入系统或已经发布。

## 目标与边界

0.2 在现有账号下增加 VPN、代理两类连接，形成“账号 → WI-FI / VPN / 代理”。账号只保留一份，不为每种连接重复创建账号。0.1.68 的 Wi-Fi 连接、认证、凭据、自动恢复与系统配置流程保持原样；新类型通过独立模块接入，不改动现有 Wi-Fi 实现。

| 类型 | 示例 | 同类同时生效 | 与其他类型 |
| --- | --- | --- | --- |
| WI-FI | 企业 Wi-Fi、热点 | 最多一个 | 可与 VPN、代理并存 |
| VPN | aTrust、Cisco Secure Client | 最多一个 | 可与 WI-FI、代理并存 |
| 代理 | Clash Verge 的配置、系统代理或 TUN | 最多一个 | 可与 WI-FI、VPN 并存，实际网络路径受客户端与系统约束 |

Clash Verge 归入“代理”，不作为 VPN 连接项。三类各有一个全账号共用的总开关；没有连接项级别的独立断开动作。

## 连接规则

1. 每类可以保存多个候选连接，但一次只选择并启用其中一个。切换某类目标，不改变另外两类的开关与选择。
2. 总开关关闭该类当前连接，保留账号、配置与上次选择。WI-FI 关闭时需要断开当前 Wi-Fi；VPN 与代理关闭时需要让各自适配器停止当前连接或接管。
3. 总开关关闭期间选择其他候选项，只更新选择；再次开启才发起连接。开启时先确认目标可用，连接结果以实际客户端或系统状态为准。
4. WI-FI 断开后，若设备没有其他可用网络，已开启的 VPN 与代理显示“等待网络”；其总开关与选择不随 WI-FI 自动改变。若系统还有以太网等可用网络，应按实际状态判定。
5. 同类切换必须先处理旧连接，再确认新连接。连接失败、客户端拒绝、需要用户认证、第三方客户端自行改动时，应显示真实状态，不把“已保存”“已选择”当作“已连接”。

## 菜单栏与配置管理

- 菜单栏是查看状态、切换和操作总开关的入口。WI-FI、VPN、代理三页横向切换；三页顶部结构一致。
- 当前连接单独显示，标题分别为“已连接网络”“已连接VPN”“已连接代理”。未连接时显示相应的关闭、等待或连接状态。
- “其他网络”“其他 VPN”“其他代理”默认收起；箭头向右，展开后向下。列表只显示名称、所属账号和连接/选择动作。
- 菜单列表按连接显示所属账号。配置管理中的账号卡片可展开，查看各类连接；菜单页的类型标签支持键盘方向键切换。
- 齿轮菜单包含“关于 WiFi Switch”“配置管理”“使用说明”“退出系统”。所有账号及连接的新增、编辑、删除均进入配置管理，不放在菜单栏。
- 配置管理先展示三类总开关和当前状态，再按现有账号展示 WI-FI、VPN、代理三组配置。每组可以添加连接，账号只新增一次。

## 接入设计

- 保留现有 Wi-Fi 代码和数据语义。新增的账号关联应通过兼容的扩展数据承载 VPN、代理，不迁移或重写 Wi-Fi 凭据。
- VPN 按客户端实现适配器。适配器需声明是否能发现配置、发起连接、断开、查询真实状态，以及是否需要交由原客户端完成认证。aTrust、Cisco Secure Client 分别验证；不假设所有 VPN 共用一套命令或协议。
- 代理按客户端/接管方式适配。Clash Verge 的配置切换、系统代理与 TUN 状态分别核验；不把代理状态推断为 VPN 状态。
- 接入前需要逐一确认客户端公开的控制接口、系统权限、企业策略和断开行为。无安全可靠控制接口时，允许引导用户到原客户端操作并如实展示状态，不通过模拟点击或修改其私有文件强行适配。

## Demo 与验收

打开 [`../../demo/0.2/index.html`](../../demo/0.2/index.html) 即可体验菜单栏、齿轮菜单、配置管理、账号与连接添加、三类切换及总开关。Demo 使用示例数据；连接结果由页面模拟，**不会操作本机 Wi-Fi、VPN 或代理**。示例密码不会保存。图标从公网加载，离线时可能缺失。

0.2 实现验收至少覆盖：账号无重复；三类选择与开关互不覆盖；每类最多一个连接生效；关闭 WI-FI 真正断开 Wi-Fi；关闭 VPN/代理让对应客户端停止；失败状态真实可见；0.1.68 原有 Wi-Fi 行为与测试保持一致。实际客户端适配与设备验收另行实施。
