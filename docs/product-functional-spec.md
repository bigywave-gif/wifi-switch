## 2. 产品定位与典型场景

WiFi Switch 用于保存多组 Wi-Fi 账号，将账号与一个或多个网络关联，并通过菜单栏或通知区域快速连接。账号凭据保存在本机系统安全存储中。

| 场景 | 产品行为 |
| --- | --- |
| 同一公司 Wi-Fi 使用不同业务账号 | 建立多个账号，分别关联相同 SSID，选择其中一个发起认证 |
| 同一账号使用多个企业网络 | 在账号下添加多个 SSID，共用用户名和密码，每次连接指定的一个网络 |
| 管理家庭 Wi-Fi、手机热点 | 添加普通密码网络，不要求企业用户名；密码不同应建立不同账号 |
| 公司和家庭之间移动 | 系统负责自动加入；应用观察当前网络并按平台规则识别账号，不抢占已加入的其他网络 |
| 网络短暂异常 | 先等待系统恢复，符合条件时有限自动重连；明确认证失败立即停止 |
| 管理员排查连接问题 | Mac 查看当前 Wi-Fi 信息；Windows 导出连接阶段诊断，结合系统侧证据分析 |

产品不提供 VPN、路由器管理、网络共享、企业账号申请或改密服务，不自动登录网页 Portal。应用中的关联数量不代表同时建立的连接数量；每块被操作的无线网卡同一时刻只连接一个 Wi-Fi。本产品不提供多网卡并发连接编排。

## 3. 核心对象与状态含义

### 3.1 账号、网络与关联

| 对象 | 内容与规则 |
| --- | --- |
| 账号 | 独立 ID、显示名称/备注、用户名、是否有密码、最近使用记录；密码独立保存 |
| 账号名称 | 用户可读名称，例如“办公账号”；普通手动新建时选填，留空显示“未命名账号” |
| Wi-Fi | 以 SSID 标识，记录认证类别；Windows 另有隐藏网络和 PEAP 信任设置 |
| 关联 | 一个账号对应多个 Wi-Fi；同一 Wi-Fi 可以属于多个不同账号，不产生额外无线热点 |
| 当前连接记录 | 关联到具体账号与 Wi-Fi；Windows 还关联网卡和系统配置名。用于状态恢复，不是服务器实时身份凭证 |
| 失败记录 | 目标、失败原因、重试次数和是否认证拒绝；保留停止重试的状态 |

同一账号共用一份密码。修改用户名或密码会影响该账号关联的全部 Wi-Fi。SSID 区分大小写，保留有效名称中的空格，不能为空或包含 NUL，长度最多 32 个 UTF-8 字节。

同一账号不能重复关联同一 SSID。Mac 还拒绝同一 Wi-Fi 下重复的非空登录用户名，防止账号匹配歧义；Windows 当前允许不同账号使用相同用户名，不能把这项规则视为两平台一致。

### 3.2 连接状态与账号身份分别判断

“系统已连接某个 SSID”与“应用知道使用了哪个账号”是两件事。系统可以已经联网，但应用显示“当前账号未识别”。

| 状态 | 展示与允许操作 |
| --- | --- |
| 尚未连接 | 显示未连接，可选择保存的账号与网络 |
| 正在连接 | 显示进度，阻止并发连接和冲突编辑；Windows 只有目标行显示“连接中…” |
| 已连接且账号已识别 | 显示 SSID 和账号名称，当前账号置顶并有绿色圆圈黑色对钩，目标网络显示正常状态 |
| 已连接但账号未知 | 显示已连接的 SSID 和未知账号，不把某个候选账号标成已连接 |
| 连接异常 | 红色状态与失败原因；可查看详情，再选择手动重连 |
| 明确认证失败 | 停止应用自动重试，提供修改账号入口；不自动打开编辑窗口 |
| 连续网络恢复失败 3 次 | 停止应用自动重试，保留异常状态，等待用户处理 |
| 无法读取网络信息 | 说明权限或系统状态问题，不以旧记录冒充当前正常连接 |

绿色状态只覆盖 Wi-Fi 关联和可用 IP，不保证互联网、DNS 实际解析、公司业务访问权限或认证账号对应的 VLAN 正确。不得仅凭 IP 地址猜测当前账号。

## 5. 账号与 Wi-Fi 配置管理

### F-01 新增账号

入口为配置管理窗口“添加账号”。填写备注、用户名、密码，扫描并勾选关联网络，也可手动添加准确 SSID。可以先保存账号，稍后补充关联。

| 所选网络 | 用户名要求 | 密码要求 |
| --- | --- | --- |
| 包含企业网络 | 必填 | 必填 |
| 普通密码网络/热点，可混选开放网络 | 选填，普通网络认证不提交用户名 | 必填 |
| 仅开放网络 | 选填，不提交 | 选填，不提交 |
| 未选择网络或类型尚未识别 | 选填；实际连接企业网络前再校验 | 必填 |

混选网络按所需条件最多的情况校验。缺少必填项时保存不可用，同时显示具体原因。扫描、连接或其他互斥操作导致暂不能保存时，也应显示原因。

保存只创建账号、关联和凭据，不测试密码，不自动连接。取消不创建配置。只关联开放网络且未填密码时，不创建密码条目。

### F-02 扫描与添加关联

扫描显示可识别名称的附近网络，标明企业认证、密码网络、开放网络或待识别类型。Mac 合并同名扫描项并按信号排序，已选网络不会因为再次扫描或暂时离开覆盖范围而消失。

没有扫描到的网络可手动添加 SSID；类型未知时在连接前再次检查。关联操作不建立真实连接，不改变当前系统网络。受密码保护的关联必须具备相应凭据。

Windows 的网络“设置”支持指定隐藏网络、实际认证类型，以及可选的 PEAP 服务器名和根证书指纹；不能通过这些设置关闭证书校验。Mac 手动填写 SSID 不等于具备 Windows 同等隐藏网络配置能力。

手机热点需实际提供可发现和可连接的 Wi-Fi。系统专有的个人热点发现能力不等于第三方扫描接口必然返回该热点；扫描不到不能直接推断热点未打开。

### F-03 修改账号与密码

账号更多菜单进入编辑。已有密码时留空表示保留原密码；通过眼睛按钮查看，关闭窗口或失去焦点后隐藏明文。修改完成后保存，取消不生效。

当前账号的用户名或密码实质变化后，保存成功才发起重连，目标是原来使用的一个 Wi-Fi。Mac 先弹出系统账号同步选择；取消选择不撤销刚保存的账号修改。认证失败保留新信息并显示错误，不把修改回退成旧密码。

只改备注、普通关联调整、原样保存、编辑其他账号、新建账号，不触发当前网络切换。Mac 在原关联被移除、已切换网络或 Wi-Fi 关闭时也不强行重连。保存失败不连接。

### F-04 移除关联与删除账号

| 操作 | 删除什么 | 保留什么 |
| --- | --- | --- |
| Wi-Fi 更多菜单“移除 Wi-Fi” | 此账号和此 Wi-Fi 的关联；相关已失效连接标记 | 账号、应用密码、其他关联、系统网络配置及现有系统连接 |
| 账号更多菜单“删除账号”，确认后执行 | 账号、所有关联、应用独立密码条目和相关记录 | 其他账号、系统另存的 Wi-Fi 凭据和网络配置 |
| 移除应用/运行 Windows 卸载程序 | 程序本体及对应安装入口 | 本机账号数据及系统安全存储；详见第 11 节 |

删除或保存过程中发生磁盘/安全存储错误，应报告失败并尽可能恢复原数据，不能显示虚假的成功结果。

## 6. 手动连接与系统账号同步

### F-05 连接、重新连接及成功判定

1. 从指定账号的目标 Wi-Fi 行点击“连接”，或更多菜单“重新连接”。重新连接也可用于当前已连接组合。
2. Mac 先选择“同步账号”“仅本次连接”或“取消”；Windows 使用当前连接流程，无此选择框。
3. 检查网络、实际认证类型、所需凭据和可操作性。已发现的缺项、类型冲突或不允许操作的配置，应在主动断开前停止。
4. 将所选凭据交给系统认证；同一 SSID 切换账号必须重新认证，不能把旧会话仍在线当成新账号成功。切换可能短暂断网。
5. 校验连接结果、目标网络和可用 IP，成功后更新当前标记及提示。失败保留账号配置，展示原因。

Mac：CoreWLAN 连接调用成功，并连续三次检查目标 SSID 和可用 IP。系统认证调用在后台运行，系统弹窗可能延长等待；调用返回后的状态确认最多约 30 秒。

Windows：收到对应网卡和配置的本次连接成功通知，再连续三次确认账号标记、SSID、配置和 IP。等待连接结果最长 90 秒；如果 Windows 仍明确处于 802.1X 认证中且未报失败，不强制拆掉正在认证的连接，提示结果尚未确认。不能把 API 返回 0 或仅写入账号标记当作成功。

Windows 手动连接其他配置失败、原先有可用连接且网卡仍断开时，会尝试一次恢复原系统配置；不重试失败目标的密码，也不覆盖用户已经切换的网络。恢复原网络不等于目标账号成功；同一配置改过凭据后，不保证能恢复旧凭据。Mac 不提供这项相同保证，可由用户选择原账号重新连接。

### F-06 Mac 系统首选账号选择

弹窗简要显示 SSID 和账号名称，通过蓝色问号“设置说明”查看解释。这里“首选账号”指该 SSID 保存的认证凭据，不是网络优先级。

| 选择 | 当前连接 | 系统保存的账号密码 |
| --- | --- | --- |
| 同步账号 | 用所选账号连接 | 连接确认成功后更新该 Wi-Fi 的系统凭据；普通网络只同步密码，开放网络不写密码 |
| 仅本次连接 | 用所选账号连接 | 连接前暂存原凭据，必要时恢复并读回核对，保留原系统账号 |
| 取消 | 不发起连接 | 不读取连接密码，不修改原记录 |

“仅本次连接”无法读取原凭据时先停止；检测到第三方并发修改时不覆盖第三方结果并报告。同步失败应明确报错并尝试回滚，不能伪装成认证密码错误。

自动恢复不弹出选择，保留原系统凭据。以上选择都不主动重排网络、不改变自动加入开关，不替代 macOS 自己的选网行为。0.1.31 历史版本调整过的顺序没有原始备份，后续版本不会猜测恢复。

### F-07 Windows 系统网络配置

同一 SSID 共用以真实网络名命名的 WLAN 配置，账号只保存在应用中，不为每个账号新增 `WiFiSwitch-编号` 条目。配置准备、自动加入、优先级、凭据和内部账号标记在连接前完成，认证成功后不再次重写配置，避免触发会话取消或覆盖系统信任状态。

新建配置使用所有用户范围；已有配置保留原范围及证书/服务器限制。同名配置指向其他 SSID、受组策略管理或不可写时明确停止。单点登录配置不静默改成普通账号认证。证书确认仍由 Windows 完成。

目标配置在发起连接前设置为自动加入并提升至最高优先级，即使本次认证失败也可能保留这些设置。此行为与 Mac 不同，当前没有“仅本次连接且完整保留系统首选”的产品选项。

旧 `WiFiSwitch-编号` 配置只在符合应用旧命名规则、属于可清理范围且未被使用时清理；状态不明、正在连接或已连接时保留，不为清理主动断网。

## 7. 系统自动加入、账号识别与配置导入

### F-08 保存记录与实时标记

更新、退出重开、重启和休眠唤醒不主动清空账号及连接记录。网络暂不可读时保留记录，但不据此将旧账号显示为当前正常连接。换网后重新核对，只有满足当前平台识别条件才更新标记。

Mac 优先使用本次应用连接的已确认账号；检测到系统连接变化后，再匹配系统保存配置。企业网络以 SSID、认证类型和保存的用户名唯一匹配；普通网络没有企业用户名，只在该网络唯一关联一个账号时识别。存在多个候选、读取被拒绝或钥匙串域信息冲突，显示未知。

后台读取只查询系统保存的用户名属性，不读取密码，不弹出授权窗口；辅助查询 4 秒超时按未知处理。系统“拷贝用户名”能取得保存值，不代表应用能获得本次 EAP 会话实时认证用户名。尤其选择“仅本次连接”后重开应用，系统保存账号可能不同于尚未中断的会话，不能保证依据保存值还原实际账号。

Windows 根据系统配置内的应用账号 UUID、网卡、SSID 和 IP 识别。系统外部独立改动凭据可能无法被这个标记反映，因此也不保证实时身份。没有匹配标记时显示未知，而不是仅按 SSID 猜一个账号。

### F-09 Mac 添加系统当前配置

自动提示必须同时满足：系统已连接且有可用 IP、成功读取系统身份、确认应用缺少对应配置、当前没有冲突编辑且该 SSID 未被用户取消提示。已唯一匹配账号时直接更新标记；读取失败、用户名无法确认、认证类型冲突或匹配歧义，不自动要求新增。

用户填写必填账号名称并点击“确认添加”后，读取导入所需的完整凭据，其中密码只在确认后读取，可能触发 macOS 钥匙串授权。此前后台识别已可能读取用户名属性，但没有读取密码。普通网络导入密码，开放网络无需密码。

取消或关闭后，同一 SSID 不再自动打扰；可从主窗口“添加此配置”手动重开。菜单栏齿轮中没有“添加当前 Wi-Fi 配置”。导入不重新连接，不改变自动加入；遇到网络改变、凭据不全、权限拒绝、冲突或取消，应停止并丢弃不适用结果。已有一致配置复用，不静默覆盖其名称或密码。

### F-10 Windows 认领当前连接

主窗口在满足以下条件时提供“认领当前连接”：应用已有保存的连接记录，对应账号及 Wi-Fi 关联仍存在；当前系统网卡、SSID、配置名与记录一致，已取得 IP 且状态可读；只有账号标记无法匹配，并且没有正在连接或认领的操作。用户确认实际使用的是记录中的账号后操作，应用写入当前配置的账号标记，并在最多 5 秒内连续核对标记及 IP。期间禁止重复认领或连接。

首次遇到完全没有应用记录的网络，不会仅因“系统已连接”就提供认领；Windows 可先手动添加账号及关联，再通过应用连接建立记录，不能像 Mac 一样导入系统密码。

认领是用户声明加状态确认，不是自动读取系统密码，也不是服务器身份查询。不可写、权限不足或无法验证时报告失败。后续轮询确认同一连接恢复，可以清除该次状态验证错误；其他操作错误不被连带清除。

## 8. 自动恢复与异常处理

### F-11 自动恢复规则

应用运行时每 5 秒检查连接。关闭管理窗口仍继续检查，退出应用则停止应用自己的检查与重试，系统自动加入仍由系统处理。

| 条件 | 行为 |
| --- | --- |
| 记录对应网络掉线或未取得可用 IP | 先等待约 10 秒让系统恢复，再按条件尝试原账号 |
| 可恢复网络故障 | 尝试间隔约 10 秒，最多连续失败 3 次 |
| 明确认证拒绝、密钥拒绝、缺少必要凭据 | 立即停止，不重复提交已被拒绝的凭据 |
| 休眠、网卡不可用、权限不足、用户关闭 Wi-Fi | 不主动打开网卡或强行连接 |
| 系统已切换其他账号/网络 | 不抢占已有连接 |
| 用户主动重连或修正当前凭据后保存 | 按相应手动连接流程重新开始 |

这里的 3 次是已有连接异常后的自动恢复尝试：若连续失败，最多发起 3 次；过程中明确认证失败则提前停止。用户首次手动连接失败，不会自动追加 3 次重试：Mac 清除本次手动连接前的旧记录，失败后不启动该目标的自动恢复；Windows 将手动失败目标直接置为停止状态，其内部计数不代表真的已经尝试了 3 次。

停止状态持久保存，退出或升级不重置重试次数。Mac 的认证停止状态不会仅因暂时读到原 SSID/IP 而解除；Windows 确认同一账号标记和健康 IP 已被系统恢复时，可清除对应失败状态，无需再次发起认证。这是现有平台差异。

3 次限制针对应用，不限制操作系统自身重试。单个网站打不开、VPN 异常或业务权限错误，不触发按业务可用性判断的自动重连。

### F-12 错误提示与用户处理

| 错误类别 | 展示与处理 |
| --- | --- |
| 用户名/密码缺失 | 指明缺项，进入修改账号后补充 |
| 明确认证拒绝 | 展示系统原因，停止重试，提供修改账号；证书或权限也可能导致认证失败 |
| 超时或结果不明 | 明确说明未确认；Windows 可能仍在认证，不直接断言密码错误 |
| Windows `0x38001` | 表示连接操作被取消，需结合阶段日志判断来源，不直接归因于管理员权限 |
| 定位/无线信息权限不足 | 引导检查系统权限；管理员权限不等于位置授权 |
| 钥匙串授权 | 由 macOS 系统弹窗处理；所需通常为登录钥匙串密码，不是 Wi-Fi 密码 |
| 配置损坏/保存失败 | 停止不安全写入，显示错误，不用空配置覆盖原数据 |
| 系统凭据同步或恢复失败 | 单独报告同步问题，不与网络认证失败混为一谈 |

认证服务器改密时，尚未中断的连接不一定立即失败，应用不能提前获知改密。系统认证弹窗中输入了新密码，也不等于应用独立账号条目已更新。

## 9. 界面与信息查看

### F-13 Mac 配置管理窗口

顶部显示连接状态、SSID、当前账号名称与账号总数。账号默认展开，当前正常账号置顶，其他账号相对顺序不变。绿色圆圈黑色对钩与连接按钮列对齐；连接正常的账号与 Wi-Fi 组合显示蓝色 Wi-Fi 图标，同名网络的其他账号及未连接条目显示灰色。

Wi-Fi 更多菜单提供重新连接、移除 Wi-Fi；仅当前已确认连接组合另有“查看 Wi-Fi 信息”。状态点可查看连接详情；点击状态或展开菜单本身不触发重连。主窗口与菜单栏使用同一连接状态。

### F-14 Mac 菜单栏与 Windows 托盘

Mac 菜单栏使用紧凑图标，弹出面板宽约 233 点。已连接网络独立展示蓝色图标、SSID 和账号，未知账号明确标注。其他网络默认收起，展开后列出保存的网络与账号组合，灰色 Wi-Fi 图标及连接按钮；仅排除当前组合，同 SSID 的其他账号仍可选。这里不是附近全部网络扫描列表。

Mac 齿轮提供配置管理、关于 WiFi Switch、使用说明和退出系统。菜单栏展开状态与管理窗口独立。关闭主窗口不退出，连接进行中暂不可退出。

Windows 托盘按账号分组，默认收起；主窗口默认展开。齿轮提供配置管理、导出诊断、退出系统。多网卡选择置于独立区域，账号数不被替换成网卡数。Windows 尚未采用 Mac 的“已连接网络/其他网络”布局。

### F-15 Mac 查看 Wi-Fi 信息

入口只对当前确认正常的账号与 Wi-Fi 组合显示，同 SSID 的其他账号也不可打开。

| 信息组 | 字段 |
| --- | --- |
| 地址 | IPv4、子网掩码、IPv4 网关、IPv6 及前缀、IPv6 网关 |
| 解析 | 当前 Wi-Fi 服务/接口对应的 DNS |
| 无线链路 | 当前接口 MAC、接入点 BSSID、信道、信号、噪声、协商速率 |
| 认证 | 系统返回的安全类型和认证类别 |

支持文字选择复制、手动刷新与每 5 秒更新。系统未提供的字段显示“未获取”；接口 MAC 可能是当前使用的私有地址。DNS 不代表 VPN/代理影响后的全部解析路径。

读取前后校验当前连接，切换账号、断开、关闭 Wi-Fi 或无法确认网络时清除内容并关闭窗口。查看不连接、不改网络、不读取密码；不推断具体 EAP 方法或本次实际认证用户名。

### F-16 版本信息与帮助

Mac 通过顶部应用菜单或菜单栏齿轮打开原生“关于”，显示名称、图标、版本、构建号、架构、最低系统要求和发布类型，均读取正在运行的包。帮助入口打开应用内本地说明。

Windows 安装文件和卸载列表提供版本信息，安装目录及开始菜单提供使用说明。两个平台版本分别以其实际包为准；开发目录变更不表示已安装应用自动更新。

## 10. 数据、凭据和权限

### 10.1 存储位置

| 数据 | Mac | Windows |
| --- | --- | --- |
| 账号元数据 | `~/Library/Application Support/WiFiSwitch/accounts.json`，权限 `0600` | `%LOCALAPPDATA%\WiFiSwitch\accounts.json` |
| 应用密码 | 登录钥匙串，服务 `org.wifiswitch.WiFiSwitch.accounts`，按账号 UUID 索引 | 当前用户凭据管理器，`WiFiSwitch/Accounts/<账号 UUID>` |
| 历史/备份 | 旧格式升级备份 `accounts-pre-v4-<UUID>.json` | 原子替换时保留 `accounts.json.backup` |
| 导入提示偏好 | UserDefaults 中保存已取消提示的 SSID | 无同等系统导入提示 |
| 连接诊断 | 未提供 Windows 同等 ZIP 日志功能 | `%LOCALAPPDATA%\WiFiSwitch\last-connection.log` 及 `diagnostics` |

JSON 包含用户名、备注、SSID、关联、使用时间与状态记录，不含密码。应用密码不写入日志或命令行。Mac 应用自有密码条目关闭 iCloud 同步；系统另外保存的 Wi-Fi 凭据仍受系统自身同步设置管理。

Mac 当前配置格式为第 4 版，兼容读取第 1–3 版并先备份迁移；Windows 格式独立。两平台文件不得互相覆盖，不提供自动跨平台迁移。

应用使用本机数据，没有产品账号注册、后台账号服务器、遥测或凭据上传功能；认证凭据交给系统无线认证链路处理。Windows 诊断由用户选择导出位置，不自动发送。

### 10.2 权限与授权边界

Mac 需按系统要求取得定位权限读取 Wi-Fi 信息，可能出现钥匙串、证书或系统认证授权。系统密码必须由用户在系统窗口输入。点击“始终允许”是对具体条目和访问主体授权，不保证更新、钥匙串锁定或权限变化后永不提示。

Windows 使用普通用户启动，安装器为当前用户安装，不强制申请管理员。位置权限、WLAN 服务权限、企业策略及认证信任是不同检查项；不应把所有失败统一解释为缺少管理员权限。应用不关闭 Credential Guard，不绕过证书校验。

## 11. 安装、升级、退出与卸载

| 环节 | Mac | Windows |
| --- | --- | --- |
| 当前交付 | arm64 内部 DMG，本地证书签名，未 Apple 公证 | x64 安装 EXE，自包含运行时，未 Authenticode 商业签名 |
| 安装入口 | DMG 中将应用拖入 Applications，再从应用程序启动 | 运行向导，开始菜单生成应用与使用说明入口 |
| 安装目录 | 通常 `/Applications/WiFi Switch.app` | 默认 `%LOCALAPPDATA%\Programs\WiFi Switch`，可选当前用户有写权限的目录 |
| 默认磁盘 | 由 Applications 所在位置决定 | 由当前用户的 LocalAppData 位置决定，常见在 C 盘，不硬编码为 C 盘 |
| 升级 | 先退出再替换应用，保留本机账号数据 | 先退出，向导默认沿用上次安装目录，保留数据 |
| 安装后连接 | 不因安装自动连接 | 不自动连接；完成页启动选项默认未勾选 |
| 退出 | 不主动断开系统 Wi-Fi | 退出常驻程序，不以退出操作主动忘记系统网络 |
| 卸载 | 将应用移到废纸篓；不会自动删除用户数据或钥匙串条目 | 已安装应用或安装目录 `Uninstall.exe`；删除程序、开始菜单和卸载登记，保留数据与凭据 |

全新用户安装为空；重装看到原账号通常是保留数据，不表示安装包预置了个人账号。当前没有“一键彻底清理所有应用数据及系统 Wi-Fi 凭据”功能。若要删除应用保存的账号及对应密码，可在应用内逐项删除；系统网络凭据是独立数据，不随此操作自动清除。备份文件中的历史元数据也不属于安全擦除承诺。

改程序安装目录不改变用户数据目录。Mac 与 Windows 的源码和制品分别在 `macos/`、`windows/`；维护一端不能隐式修改另一端安装产物。

## 12. Windows 诊断导出

### F-17 导出与排查内容

主窗口底部、托盘齿轮及异常详情提供“导出诊断”，连接过程中也可操作。用户选择位置生成 ZIP，包含说明和最近最多 10 次连接记录，每次最多保留末尾 1500 行，超出会注明截断。

记录包括会话 ID、带时区时间、累计耗时、阶段开始/结束、网卡和配置准备、凭据是否存在、WLAN/802.1X 通知、原始 API/原因码、状态核对和最终结果。等待阶段约每 5 秒记录一次，新增日志后台约每秒保存。

ZIP 不含账号文件、密码、用户名、备注、SSID、IP/MAC、完整配置 XML 或原始认证载荷；可能包含不可逆哈希用于关联配置。`END success=True` 表示应用已完成验证与状态保存，`active=True` 表示记录结束时流程尚未结束，均须结合阶段看待。

系统未返回明确拒绝原因时，应用日志可能仍不足以定位，需要 Windows WLAN/EAP 或认证服务器日志。导出成功不代表认证缺陷已修复。

### 13.3 明确限制

- 无法可靠读取企业认证服务器上的实时账号身份；系统保存用户名和应用账号标记均有边界。
- 不保证消除所有钥匙串、服务器证书或系统认证提示，不以关闭安全校验实现免提示。
- 不支持 EAP-TLS 客户端证书管理、第三方 EAP 全覆盖、网页 Portal 自动登录。
- 不提供在线自动更新、账号云同步、跨平台迁移、后台远程管理或完整数据擦除工具。
- 当前发布的 Mac 包不适用于 Intel Mac；当前 Windows 包目标为 Intel/AMD x64。
- Windows 尚未覆盖 Mac 最新的系统配置导入、同步选择、网络详情和菜单栏布局，不能宣称两端完全一致。

仅补文档不虚增应用版本，不改写已发布包。新打包版本须更新平台版本号、构建信息、README 和版本记录；应用内版本以实际运行的包为准。发布流程见 [发布规则](../macos/docs/release-policy.md)。
