## 2. 产品定位与典型场景

WiFi Switch 用于保存多组 Wi-Fi 账号，将账号与一个或多个网络关联，并通过菜单栏或通知区域快速连接。账号凭据保存在本机系统安全存储中。

| 场景 | 产品行为 |
| --- | --- |
| 同一公司 Wi-Fi 使用不同业务账号 | 建立多个账号，分别关联相同 SSID，选择其中一个发起认证 |
| 同一账号使用多个企业网络 | 在账号下添加多个 SSID，共用用户名和密码，每次连接指定的一个网络 |
| 管理家庭 Wi-Fi、手机热点 | 添加普通密码网络，不要求企业用户名；密码不同应建立不同账号 |
| 公司和家庭之间移动 | 系统负责自动加入；应用观察当前网络并按平台规则识别账号，不抢占已加入的其他网络 |
| 网络短暂异常 | Mac 等待系统恢复后询问用户是否重连；Windows 按原有自动恢复规则处理 |
| 管理员排查连接问题 | Mac 查看当前 Wi-Fi 信息；Windows 导出连接阶段诊断，结合系统侧证据分析 |

产品不提供 VPN、路由器管理、网络共享、企业账号申请或改密服务，不自动登录网页 Portal。应用中的关联数量不代表同时建立的连接数量；每块被操作的无线网卡同一时刻只连接一个 Wi-Fi。本产品不提供多网卡并发连接编排。

## 3. 核心对象与状态含义

### 3.1 账号、网络与关联

| 对象 | 内容与规则 |
| --- | --- |
| 账号 | 独立 ID、显示名称/备注、用户名、是否有密码、最近使用记录；密码独立保存 |
| 账号名称 | 用户可读名称，例如“办公账号”；普通手动新建时选填，留空显示“未命名账号” |
| Wi-Fi | 以 SSID 标识，记录认证类别；Windows 另有隐藏网络和 PEAP 信任设置 |
| 关联 | 一个账号对应多个 Wi-Fi；同一 Wi-Fi 可以属于多个不同账号，不产生额外无线热点 |
| 当前连接记录 | 关联到具体账号与 Wi-Fi；Windows 还关联网卡和系统配置名。用于状态恢复，不是服务器实时身份凭证 |
| 失败记录 | 目标、失败原因、重试次数和是否认证拒绝；保留停止重试的状态 |

同一账号共用一份密码。修改用户名或密码会影响该账号关联的全部 Wi-Fi。SSID 区分大小写，保留有效名称中的空格，不能为空或包含 NUL，长度最多 32 个 UTF-8 字节。

同一账号不能重复关联同一 SSID。Mac 还拒绝同一 Wi-Fi 下重复的非空登录用户名，防止账号匹配歧义；Windows 当前允许不同账号使用相同用户名，不能把这项规则视为两平台一致。

### 3.2 连接状态与账号身份分别判断

“系统已连接某个 SSID”与“应用知道使用了哪个账号”是两件事。系统可以已经联网，但应用显示“当前账号未识别”。

| 状态 | 展示与允许操作 |
| --- | --- |
| 尚未连接 | 显示未连接，可选择保存的账号与网络 |
| 正在连接 | 显示进度，阻止并发连接和冲突编辑；Windows 只有目标行显示“连接中…” |
| 已连接且账号已识别 | 显示 SSID 和账号名称，当前账号置顶，核对一致且互联网正常显示绿色；未核对灰色、确认不同黄色、网络异常红色，与菜单一致 |
| 已连接但账号未知 | 显示已连接的 SSID 和未知账号，不把某个候选账号标成已连接 |
| 连接异常 | 红色状态与失败原因；可查看详情，再选择手动重连 |
| 明确认证失败 | 停止应用自动重试，提供修改账号入口；不自动打开编辑窗口 |
| 网络恢复失败 | Mac 保留异常状态等待用户处理；Windows 连续失败 3 次后停止自动重试 |
| 无法读取网络信息 | 说明权限或系统状态问题，不以旧记录冒充当前正常连接 |

主配置面板和菜单共用核对与互联网状态；应用发起的企业连接按下文 0.1.59 规则基于完成的关联操作展示状态。互联网检测不保证所有网站、公司业务访问权限或认证账号对应的 VLAN 正确。不得仅凭 IP 地址猜测当前账号。

## 5. 账号与 Wi-Fi 配置管理

### F-01 新增账号

入口为配置管理窗口“添加账号”。填写备注、用户名、密码，扫描并勾选关联网络，也可手动添加准确 SSID。可以先保存账号，稍后补充关联。

| 所选网络 | 用户名要求 | 密码要求 |
| --- | --- | --- |
| 包含企业网络 | 必填 | 必填 |
| 普通密码网络/热点，可混选开放网络 | 选填，普通网络认证不提交用户名 | 必填 |
| 仅开放网络 | 选填，不提交 | 选填，不提交 |
| 未选择网络或类型尚未识别 | 选填；实际连接企业网络前再校验 | 必填 |

混选网络按所需条件最多的情况校验。缺少必填项时保存不可用，同时显示具体原因。扫描、连接或其他互斥操作导致暂不能保存时，也应显示原因。

保存只创建账号、关联和凭据，不测试密码，不自动连接。取消不创建配置。只关联开放网络且未填密码时，不创建密码条目。

### F-02 扫描与添加关联

扫描显示可识别名称的附近网络，标明企业认证、密码网络、开放网络或待识别类型。Mac 合并同名扫描项并按信号排序，已选网络不会因为再次扫描或暂时离开覆盖范围而消失。

没有扫描到的网络可手动添加 SSID；类型未知时在连接前再次检查。关联操作不建立真实连接，不改变当前系统网络。受密码保护的关联必须具备相应凭据。

Windows 的网络“设置”支持指定隐藏网络、实际认证类型，以及可选的 PEAP 服务器名和根证书指纹；不能通过这些设置关闭证书校验。Mac 手动填写 SSID 不等于具备 Windows 同等隐藏网络配置能力。

手机热点需实际提供可发现和可连接的 Wi-Fi。系统专有的个人热点发现能力不等于第三方扫描接口必然返回该热点；扫描不到不能直接推断热点未打开。

### F-03 修改账号与密码

账号更多菜单进入编辑。已有密码时留空表示保留原密码；通过眼睛按钮查看，关闭窗口或失去焦点后隐藏明文。修改完成后保存，取消不生效。

当前账号的用户名或密码实质变化后，保存成功才发起重连，目标是原来使用的一个 Wi-Fi。Mac 先弹出系统账号同步选择；取消选择不撤销刚保存的账号修改。认证失败保留新信息并显示错误，不把修改回退成旧密码。

只改备注、普通关联调整、原样保存、编辑其他账号、新建账号，不触发当前网络切换。Mac 在原关联被移除、已切换网络或 Wi-Fi 关闭时也不强行重连。保存失败不连接。

### F-04 移除关联与删除账号

| 操作 | 删除什么 | 保留什么 |
| --- | --- | --- |
| Wi-Fi 更多菜单“移除 Wi-Fi” | 此账号和此 Wi-Fi 的关联；相关已失效连接标记 | 账号、应用密码、其他关联、系统网络配置及现有系统连接 |
| 账号更多菜单“删除账号”，确认后执行 | 账号、所有关联、应用独立密码条目和相关记录 | 其他账号、系统另存的 Wi-Fi 凭据和网络配置 |
| 移除应用/运行 Windows 卸载程序 | 程序本体及对应安装入口 | 本机账号数据及系统安全存储；详见第 11 节 |

删除或保存过程中发生磁盘/安全存储错误，应报告失败并尽可能恢复原数据，不能显示虚假的成功结果。

## 6. 手动连接与系统账号同步

### F-05 连接、重新连接及成功判定

1. 从指定账号的目标 Wi-Fi 行点击“连接”，或更多菜单“重新连接”。重新连接也可用于当前已连接组合。
2. Mac 先选择“同步账号”“仅本次连接”或“取消”；Windows 使用当前连接流程，无此选择框。
3. 检查网络、实际认证类型、所需凭据和可操作性。已发现的缺项、类型冲突或不允许操作的配置，应在主动断开前停止。
4. 将所选凭据交给系统认证；同一 SSID 切换账号必须重新认证，不能把旧会话仍在线当成新账号成功。切换可能短暂断网。
5. 校验连接结果、目标网络和可用 IP，成功后更新当前标记及提示。失败保留账号配置，展示原因。

Mac：CoreWLAN 连接调用成功，并连续三次检查目标 SSID 和可用 IP。系统认证调用在后台运行，系统弹窗可能延长等待；调用返回后的状态确认最多约 30 秒。

Windows：收到对应网卡和配置的本次连接成功通知，再连续三次确认账号标记、SSID、配置和 IP。等待连接结果最长 90 秒；如果 Windows 仍明确处于 802.1X 认证中且未报失败，不强制拆掉正在认证的连接，提示结果尚未确认。不能把 API 返回 0 或仅写入账号标记当作成功。

Windows 手动连接其他配置失败、原先有可用连接且网卡仍断开时，会尝试一次恢复原系统配置；不重试失败目标的密码，也不覆盖用户已经切换的网络。恢复原网络不等于目标账号成功；同一配置改过凭据后，不保证能恢复旧凭据。Mac 不提供这项相同保证，可由用户选择原账号重新连接。

### F-06 Mac 系统首选账号选择

弹窗简要显示 SSID 和账号名称，通过蓝色问号“设置说明”查看解释。这里“首选账号”指该 SSID 保存的认证凭据，不是网络优先级。

| 选择 | 当前连接 | 系统保存的账号密码 |
| --- | --- | --- |
| 同步账号 | 用所选账号连接 | 连接确认成功后更新该 Wi-Fi 的系统凭据；普通网络只同步密码，开放网络不写密码 |
| 仅本次连接 | 用所选账号连接 | 连接前暂存原凭据，必要时恢复并读回核对，保留原系统账号 |
| 取消 | 不发起连接 | 不读取连接密码，不修改原记录 |

“仅本次连接”无法读取原凭据时先停止；检测到第三方并发修改时不覆盖第三方结果并报告。同步失败应明确报错并尝试回滚，不能伪装成认证密码错误。

自动恢复不弹出选择，保留原系统凭据。以上选择都不主动重排网络、不改变自动加入开关，不替代 macOS 自己的选网行为。0.1.31 历史版本调整过的顺序没有原始备份，后续版本不会猜测恢复。

### F-07 Windows 系统网络配置

同一 SSID 共用以真实网络名命名的 WLAN 配置，账号只保存在应用中，不为每个账号新增 `WiFiSwitch-编号` 条目。配置准备、自动加入、优先级、凭据和内部账号标记在连接前完成，认证成功后不再次重写配置，避免触发会话取消或覆盖系统信任状态。

新建配置使用所有用户范围；已有配置保留原范围及证书/服务器限制。同名配置指向其他 SSID、受组策略管理或不可写时明确停止。单点登录配置不静默改成普通账号认证。证书确认仍由 Windows 完成。

目标配置在发起连接前设置为自动加入并提升至最高优先级，即使本次认证失败也可能保留这些设置。此行为与 Mac 不同，当前没有“仅本次连接且完整保留系统首选”的产品选项。

旧 `WiFiSwitch-编号` 配置只在符合应用旧命名规则、属于可清理范围且未被使用时清理；状态不明、正在连接或已连接时保留，不为清理主动断网。

## 7. 系统自动加入、账号识别与配置导入

### F-08 保存记录与实时标记

更新、退出重开、重启和休眠唤醒不主动清空账号及连接记录。网络暂不可读时保留记录，但不据此将旧账号显示为当前正常连接。换网后重新核对，只有满足当前平台识别条件才更新标记。

Mac 优先使用本次应用连接的已确认账号；检测到系统连接变化后，再匹配系统保存配置。企业网络以 SSID、认证类型和保存的用户名唯一匹配；普通网络没有企业用户名，只在该网络唯一关联一个账号时识别。存在多个候选、读取被拒绝或钥匙串域信息冲突，显示未知。

后台身份读取只查询系统保存的用户名属性。唯一匹配后先在禁止交互的辅助进程中核对密码（4 秒上限、30 秒缓存）；0.1.56 在启动和系统回切时，静默不可读且没有本次连接一致证据会自动继续可授权读取，既有许可由系统复用；失败或取消后显示可点击的灰色信息标记，可手动重试。已成功保存并回读一致的证据仅保留于当前进程、账号与连接；再次静默读取失败不推翻已确认的一致。后台仍检查真实差异，断开／换网／连接事件／休眠使证据失效。系统“拷贝用户名”返回保存值，不代表本次 EAP 会话实时认证用户名；“仅本次连接”的活跃应用会话不拿系统默认凭据误判。

Windows 根据系统配置内的应用账号 UUID、网卡、SSID 和 IP 识别。系统外部独立改动凭据可能无法被这个标记反映，因此也不保证实时身份。没有匹配标记时显示未知，而不是仅按 SSID 猜一个账号。

### F-09 Mac 添加系统当前配置

自动提示必须同时满足：系统已连接且有可用 IP、成功读取系统身份、确认应用缺少对应配置、当前没有冲突编辑且该 SSID 未被用户取消提示。已唯一匹配账号时直接更新标记；读取失败、用户名无法确认、认证类型冲突或匹配歧义，不自动要求新增。

用户可点击菜单栏未知账号旁的黄色叹号打开添加窗口。填写必填的“Wi-Fi 描述”（保存为账号名称）并点击“添加”后，读取导入所需的完整凭据，其中密码只在确认后读取，可能触发 macOS 钥匙串授权。新配置未确认前不读取密码；已有匹配账号可执行上述静默核对。普通网络导入密码，开放网络无需密码。

普通 Wi-Fi/个人热点先使用 Security 接口按服务 AirPort 和精确 SSID 查找密码条目，枚举引用后逐项读取；避免 CoreWLAN 用户域错误阻断已保存热点密码导入。标准条目不存在时才尝试 CoreWLAN；取消或拒绝授权立即停止，不换路径重复请求。不同密码、缺失数据或条目不再匹配时不导入。界面分别报告认证方式不可读、凭据不完整及钥匙串授权/接口错误，保留必要阶段和错误码，不包含密码。企业凭据和 CoreWLAN 后备读取均为用户域优先：完整凭据立即返回，仅未找到条目时查询系统域；读取错误、取消或凭据不完整停止。不会在用户凭据已可用时额外读取系统域密码；仍核对目标用户名和认证类别。

取消或关闭后不新增配置，当前未知连接保持黄色叹号，同一 SSID 不再自动打扰；可点击菜单栏黄色叹号或主窗口“添加此配置”手动重开。成功添加且互联网检测通过后当前连接显示绿色对钩。菜单栏齿轮中没有“添加当前 Wi-Fi 配置”。导入不重新连接，不改变自动加入；遇到网络改变、凭据不全、权限拒绝、冲突或取消，应停止并丢弃不适用结果。已有一致配置复用，不静默覆盖其名称或密码。

0.1.50 起，应用保存后必须回读一致才显示正常；后续比较核对导入来源，来源变化按不可用处理。发现差异时对系统和应用密码各再读一次，身份、来源或任一密码在读取中变化都不报告确认不同。来源只保留于本次进程和连接范围，断开／换网清除。诊断记录 `~/Library/Logs/WiFiSwitch/credential-sync.log` 包含时间、版本、进程号、阶段、结果、来源类别、错误码；不含 SSID、用户名、账号 ID、密码及摘要，限长、仅用户可读、不会上传。

已有账号且关联存在、密码经两次稳定比较确认不一致时，互联网可用状态下显示黄色叹号；点击后确认只更新应用密码，保留 ID、名称、用户名与关联，不重新连接。自动核对不自行覆盖密码。旧后台结果不得覆盖新连接／导入结果。已确认过期账号暂停应用自动重试，保存或手动连接成功后恢复。

企业账号存在但 Wi-Fi 未关联时，以用户名跨账号唯一匹配，展示目标账号后点击添加，补充关联而不新建账号。若同时发现密码变化，必须再明确点击“添加并更新”，告知所有关联网络共用密码；关联与密码原子保存，失败回滚。多候选不猜选；普通网络无用户名，不跨 SSID 按同密码合并。用户名与 Wi-Fi 都无对应记录时才新建账号并关联。网络、身份或目标账号在读取期间变化时丢弃结果。

### F-10 Windows 认领当前连接

主窗口在满足以下条件时提供“认领当前连接”：应用已有保存的连接记录，对应账号及 Wi-Fi 关联仍存在；当前系统网卡、SSID、配置名与记录一致，已取得 IP 且状态可读；只有账号标记无法匹配，并且没有正在连接或认领的操作。用户确认实际使用的是记录中的账号后操作，应用写入当前配置的账号标记，并在最多 5 秒内连续核对标记及 IP。期间禁止重复认领或连接。

首次遇到完全没有应用记录的网络，不会仅因“系统已连接”就提供认领；Windows 可先手动添加账号及关联，再通过应用连接建立记录，不能像 Mac 一样导入系统密码。

认领是用户声明加状态确认，不是自动读取系统密码，也不是服务器身份查询。不可写、权限不足或无法验证时报告失败。后续轮询确认同一连接恢复，可以清除该次状态验证错误；其他操作错误不被连带清除。

## 8. 自动恢复与异常处理

### F-11 自动恢复规则

应用运行时每 5 秒检查连接。关闭管理窗口仍继续检查，退出应用则停止应用自己的检查与重试，系统自动加入仍由系统处理。

| 条件 | 行为 |
| --- | --- |
| 记录对应网络掉线或未取得可用 IP | Mac 默认等待约 3 秒后询问用户，确认后尝试一次原账号；Windows 保持原自动恢复 |
| 可恢复网络故障 | Mac 每次确认只执行一次；Windows 保持最多连续失败 3 次 |
| 明确认证拒绝、密钥拒绝、缺少必要凭据 | 立即停止，不重复提交已被拒绝的凭据 |
| 休眠、网卡不可用、权限不足、用户关闭 Wi-Fi | 不主动打开网卡或强行连接 |
| 系统已切换其他账号/网络 | 不抢占已有连接 |
| macOS 关闭再打开系统 Wi-Fi | 等待系统加入并读取其结果，不启动旧账号恢复 |
| 用户主动重连或修正当前凭据后保存 | 按相应手动连接流程重新开始 |

Mac 0.1.57 区分应用重新认证与系统自行恢复：应用实际重连使用最后连接账号，清理残留关联、提交凭据并连续验证 SSID/IP，保留本次账号会话与原系统默认凭据。系统在等待、扫描或授权期间已自行恢复时，不提交目标账号、不报告目标账号成功，转为读取系统身份。连接变化后清除绑定旧账号的成功提示，不清除无关错误。系统保存用户名仅为识别依据，不是认证服务器身份查询。

Windows 的 3 次是已有连接异常后的自动恢复尝试：若连续失败，最多发起 3 次；过程中明确认证失败则提前停止。Mac 从 0.1.60 起每次确认仅尝试一次。用户首次手动连接失败，不会自动追加 3 次重试：Mac 清除本次手动连接前的旧记录，失败后不启动该目标的自动恢复；Windows 将手动失败目标直接置为停止状态，其内部计数不代表真的已经尝试了 3 次。

停止状态持久保存，退出或升级不重置重试次数。Mac 的认证停止状态不会仅因暂时读到原 SSID/IP 而解除；Windows 确认同一账号标记和健康 IP 已被系统恢复时，可清除对应失败状态，无需再次发起认证。这是现有平台差异。

Windows 的 3 次限制针对应用，不限制操作系统自身重试。单个网站打不开、VPN 异常或业务权限错误，不触发按业务可用性判断的自动重连。

### F-12 错误提示与用户处理

| 错误类别 | 展示与处理 |
| --- | --- |
| 用户名/密码缺失 | 指明缺项，进入修改账号后补充 |
| 明确认证拒绝 | 展示系统原因，停止重试，提供修改账号；证书或权限也可能导致认证失败 |
| 超时或结果不明 | 明确说明未确认；Windows 可能仍在认证，不直接断言密码错误 |
| Windows `0x38001` | 表示连接操作被取消，需结合阶段日志判断来源，不直接归因于管理员权限 |
| 定位/无线信息权限不足 | 引导检查系统权限；管理员权限不等于位置授权 |
| 钥匙串授权 | 由 macOS 系统弹窗处理；所需通常为登录钥匙串密码，不是 Wi-Fi 密码 |
| 配置损坏/保存失败 | 停止不安全写入，显示错误，不用空配置覆盖原数据 |
| 系统凭据同步或恢复失败 | 单独报告同步问题，不与网络认证失败混为一谈 |

认证服务器改密时，尚未中断的连接不一定立即失败，应用不能提前获知改密。系统认证弹窗中输入了新密码，也不等于应用独立账号条目已更新。

## 9. 界面与信息查看

### F-13 Mac 配置管理窗口

顶部显示连接状态、SSID、当前账号名称与账号总数。账号默认展开，当前正常账号置顶，其他账号相对顺序不变。状态标识与连接按钮列对齐，颜色和符号跟随菜单的密码与互联网核对结果；连接正常的账号与 Wi-Fi 组合显示蓝色 Wi-Fi 图标，同名网络的其他账号及未连接条目显示灰色。

Wi-Fi 更多菜单提供重新连接、移除 Wi-Fi；仅当前已确认连接组合另有“查看 Wi-Fi 信息”。状态点可查看连接详情；点击状态或展开菜单本身不触发重连。主窗口与菜单栏使用同一连接状态。

### F-14 Mac 菜单栏与 Windows 托盘

Mac 菜单栏使用紧凑图标，弹出面板宽约 233 点。已连接网络独立展示蓝色图标、SSID 和账号，已确认账号且互联网探测通过时显示绿色对钩，未知账号显示可点击的黄色叹号，点击可添加系统当前配置。断开连接或 Wi-Fi 关闭显示红色叉号；等待 IP 的前 30 秒或正在确认使用灰色时钟，持续无 IP 或互联网探测失败显示红色叉号，无法读取名称或没有可用网卡使用灰色问号，不将权限不足当作断网。已有账号密码确认变化时显示可点击黄色提示，进入已有账号更新流程；启动及回切先按 0.1.56 规则自动核对；仍不可用使用可点击的灰色信息标记，点击打开“核对账户信息”；不冒充密码变化，不重复新增账号。核对一致关闭窗口且不重写密码；不同则变黄并切换为更新确认，用户再次点击更新后才写入并回读。失败时窗口显示橙色错误，保持灰色；取消不修改凭据。其他网络默认收起，展开后列出保存的网络与账号组合，灰色 Wi-Fi 图标及连接按钮；仅排除当前组合，同 SSID 的其他账号仍可选。这里不是附近全部网络扫描列表。菜单栏不在“其他网络”下方重复显示操作结果通知；配置管理面板的通知原样保留，菜单栏的连接进度和认证等待提示也保留。

Mac 齿轮按三组排列：“关于 WiFi Switch”独立一组；“配置管理、使用说明”为一组；“退出系统”独立一组，组间使用分隔线。菜单栏展开状态与管理窗口独立。关闭主窗口不退出，连接进行中暂不可退出。

Windows 托盘按账号分组，默认收起；主窗口默认展开。齿轮提供配置管理、导出诊断、退出系统。多网卡选择置于独立区域，账号数不被替换成网卡数。Windows 尚未采用 Mac 的“已连接网络/其他网络”布局。

### F-15 Mac 查看 Wi-Fi 信息

入口只对当前确认正常的账号与 Wi-Fi 组合显示，同 SSID 的其他账号也不可打开。

| 信息组 | 字段 |
| --- | --- |
| 地址 | IPv4、子网掩码、IPv4 网关、IPv6 及前缀、IPv6 网关 |
| 解析 | 当前 DNS（Wi-Fi 接口解析器）、DNS（手动设置）、DNS（自动获取），三种来源分开显示 |
| 无线链路 | 当前接口 MAC、接入点 BSSID、信道、信号、噪声、协商速率 |
| 认证 | 系统返回的安全类型和认证类别 |

支持文字选择复制、手动刷新与每 5 秒更新。系统未提供的字段显示“未获取”；接口 MAC 可能是当前使用的私有地址。当前 DNS 从系统接口作用域解析器读取，多个地址按系统顺序显示；无法确认时显示“未确认”，不根据手动配置猜测。手动 DNS 来自已应用的系统设置，自动 DNS 来自网络提供的数据，同一地址也保留各自来源。系统设置中的修改需保存后才反映。当前 DNS 不代表每次请求实际命中的服务器，VPN、加密 DNS、按域名分流可能使用其他解析器。

读取前后校验当前连接，切换账号、断开、关闭 Wi-Fi 或无法确认网络时清除内容并关闭窗口。查看不连接、不改网络、不读取密码；不推断具体 EAP 方法或本次实际认证用户名。

### F-16 版本信息与帮助

Mac 通过顶部应用菜单或菜单栏齿轮打开原生“关于”，显示名称、图标、版本、构建号、架构、最低系统要求和发布类型，均读取正在运行的包。帮助入口打开应用内本地说明。

Windows 安装文件和卸载列表提供版本信息，安装目录及开始菜单提供使用说明。两个平台版本分别以其实际包为准；开发目录变更不表示已安装应用自动更新。

## 10. 数据、凭据和权限

### 10.1 存储位置

| 数据 | Mac | Windows |
| --- | --- | --- |
| 账号元数据 | `~/Library/Application Support/WiFiSwitch/accounts.json`，权限 `0600` | `%LOCALAPPDATA%\WiFiSwitch\accounts.json` |
| 应用密码 | 登录钥匙串，服务 `org.wifiswitch.WiFiSwitch.accounts`，按账号 UUID 索引 | 当前用户凭据管理器，`WiFiSwitch/Accounts/<账号 UUID>` |
| 历史/备份 | 旧格式升级备份 `accounts-pre-v4-<UUID>.json` | 原子替换时保留 `accounts.json.backup` |
| 导入提示偏好 | UserDefaults 中保存已取消提示的 SSID | 无同等系统导入提示 |
| 连接诊断 | 未提供 Windows 同等 ZIP 日志功能 | `%LOCALAPPDATA%\WiFiSwitch\last-connection.log` 及 `diagnostics` |

JSON 包含用户名、备注、SSID、关联、使用时间与状态记录，不含密码。应用密码不写入日志或命令行。Mac 应用自有密码条目关闭 iCloud 同步；系统另外保存的 Wi-Fi 凭据仍受系统自身同步设置管理。

Mac 当前配置格式为第 4 版，兼容读取第 1–3 版并先备份迁移；Windows 格式独立。两平台文件不得互相覆盖，不提供自动跨平台迁移。

应用使用本机数据，没有产品账号注册、后台账号服务器、遥测或凭据上传功能；认证凭据交给系统无线认证链路处理。Windows 诊断由用户选择导出位置，不自动发送。

### 10.2 权限与授权边界

Mac 需按系统要求取得定位权限读取 Wi-Fi 信息，可能出现钥匙串、证书或系统认证授权。系统授权密码必须由用户在系统窗口输入。访问具体密码条目的“始终允许”与使用系统钥匙串时的管理员名称／密码授权不同，应用不能强制系统提供“始终允许”。点击“始终允许”是对具体条目和访问主体授权，不保证更新、钥匙串锁定或权限变化后永不提示。

Windows 使用普通用户启动，安装器为当前用户安装，不强制申请管理员。位置权限、WLAN 服务权限、企业策略及认证信任是不同检查项；不应把所有失败统一解释为缺少管理员权限。应用不关闭 Credential Guard，不绕过证书校验。

## 11. 安装、升级、退出与卸载

| 环节 | Mac | Windows |
| --- | --- | --- |
| 当前交付 | arm64 内部 DMG，本地证书签名，未 Apple 公证 | x64 安装 EXE，自包含运行时，未 Authenticode 商业签名 |
| 安装入口 | DMG 中将应用拖入 Applications，再从应用程序启动 | 运行向导，开始菜单生成应用与使用说明入口 |
| 安装目录 | 通常 `/Applications/WiFi Switch.app` | 默认 `%LOCALAPPDATA%\Programs\WiFi Switch`，可选当前用户有写权限的目录 |
| 默认磁盘 | 由 Applications 所在位置决定 | 由当前用户的 LocalAppData 位置决定，常见在 C 盘，不硬编码为 C 盘 |
| 升级 | 先退出再替换应用，保留本机账号数据 | 先退出，向导默认沿用上次安装目录，保留数据 |
| 安装后连接 | 不因安装自动连接 | 不自动连接；完成页启动选项默认未勾选 |
| 退出 | 不主动断开系统 Wi-Fi | 退出常驻程序，不以退出操作主动忘记系统网络 |
| 卸载 | 将应用移到废纸篓；不会自动删除用户数据或钥匙串条目 | 已安装应用或安装目录 `Uninstall.exe`；删除程序、开始菜单和卸载登记，保留数据与凭据 |

全新用户安装为空；重装看到原账号通常是保留数据，不表示安装包预置了个人账号。当前没有“一键彻底清理所有应用数据及系统 Wi-Fi 凭据”功能。若要删除应用保存的账号及对应密码，可在应用内逐项删除；系统网络凭据是独立数据，不随此操作自动清除。备份文件中的历史元数据也不属于安全擦除承诺。

改程序安装目录不改变用户数据目录。Mac 与 Windows 的源码和制品分别在 `macos/`、`windows/`；维护一端不能隐式修改另一端安装产物。

## 12. Windows 诊断导出

### F-17 导出与排查内容

主窗口底部、托盘齿轮及异常详情提供“导出诊断”，连接过程中也可操作。用户选择位置生成 ZIP，包含说明和最近最多 10 次连接记录，每次最多保留末尾 1500 行，超出会注明截断。

记录包括会话 ID、带时区时间、累计耗时、阶段开始/结束、网卡和配置准备、凭据是否存在、WLAN/802.1X 通知、原始 API/原因码、状态核对和最终结果。等待阶段约每 5 秒记录一次，新增日志后台约每秒保存。

ZIP 不含账号文件、密码、用户名、备注、SSID、IP/MAC、完整配置 XML 或原始认证载荷；可能包含不可逆哈希用于关联配置。`END success=True` 表示应用已完成验证与状态保存，`active=True` 表示记录结束时流程尚未结束，均须结合阶段看待。

系统未返回明确拒绝原因时，应用日志可能仍不足以定位，需要 Windows WLAN/EAP 或认证服务器日志。导出成功不代表认证缺陷已修复。

## 0.1.51 补充：Mac 互联网检查

每次连接／唤醒触发，30 秒缓存。使用 Network.framework TLS 连接并要求 Wi-Fi 接口类型，分别探测 Apple 和 Microsoft 公网域名的 443 端口；正常系统证书校验、每端点 4 秒上限、任一成功即通过，全部失败再试一轮。失败显示红叉“互联网检测未通过”；不因检测失败自动重连或改配置。网络切换、断开和睡眠会使旧检测结果失效，恢复后重新检查。

该检测证明外部 TLS 连通性，不等于所有网页／公司服务可用；代理、VPN、门户或端点屏蔽可能导致局部可用但检测失败。不发送账号密码，不调整系统安全保护或网络首选。主面板原有布局和连接通知保持不变。首次导入无需额外人工核对；必要的系统钥匙串授权仍保留，无法授权不得宣称凭据一致。

## 0.1.53 补充：授权调用边界

常规后台密码比较由禁止交互的 helper 执行；0.1.56 增加下文限定的启动与回切自动核对。CoreWLAN 通知按 350 毫秒合并；自身切换期间的通知不触发竞争核对。编辑读取应用密码，系统配置导入只在用户确认后进行。

已有账号导入需二次确认时，在同一窗口内复用刚读取的快照，最多保留 30 秒；取消、关闭、连接事件、超时后不得复用。凭据不落盘，不缓存管理员密码。同步后的每个域只做一次最终回读，保留回滚、第三方修改保护和原账号保留语义。必要的系统钥匙串读写授权仍由 macOS 决定，不承诺零弹窗。


## 0.1.54 补充：灰色状态的手动核对

手动入口中，用户点击“核对”调用可授权的系统配置读取；自动启动与回切核对见下文。确认不同后切换更新窗口并显示黄色，未确认不修改密码。读取失败在窗口内以橙色文字显示，记录 `verificationReadFailed` 或 `importReadFailed` 至 `~/Library/Logs/WiFiSwitch/credential-sync.log`，仅包含固定事件、结果、可取得的错误码，不含账号和密码。网络异常的红色状态优先于凭据提示。


## 0.1.56 补充：系统回切自动核对与授权目标说明

每次启动和系统回切后，先唯一匹配账号并静默比较，受限且没有当前连接的一致证据时自动使用与导入相同的读取接口继续核对，无需再次点灰色图标。既有许可交给 macOS 复用，不修改授权范围或保存管理员密码。未登记网络仍为黄色并由用户确认导入。

同一连接失败／取消后不会因轮询或重复通知连续申请；观察到离开网络或休眠后重置尝试机会。成功核对后的新连接通知可自动重新核对；350 毫秒合并通知，正在授权时阻止竞争编辑和切换。网络／账号变化后的旧结果丢弃，不把授权失败伪报为密码不同。

一致要求真实密码读取与保存值相同；确认不同仍需二次稳定读取，两侧身份、来源或密码变化时不判为不同。仅明确确认更新后写入并回读，既有“仅本次连接”语义不变。菜单和主面板共用状态：已登记、密码一致且互联网探测通过为绿；未登记／密码不同为黄；读取失败为灰；网络异常为红。

授权前的应用提示显示账号描述、Wi-Fi 名称及适用的企业用户名。自动核对使用独立说明窗口，添加／更新显示在原窗口内；标准个人网络查询附带相同操作说明，CoreWLAN 的系统弹窗不可自定义，用应用提示补充目标信息。不得记录或显示实际密码。系统是否接受既有授权仍受条目 ACL、签名与设备策略控制；不承诺一次管理员许可永久免提示。

自动诊断阶段为 automaticVerificationStarted／Completed／Failed，日志仍不包含网络名、用户名、密码或摘要。旧版本的启动机会 UserDefaults 标记不再控制核对，无需迁移账号或钥匙串。

## 0.1.58 历史记录：企业连接请求与实际身份

以下为 0.1.58 的历史行为，已由 0.1.59 调整。

应用手动连接或自动重连企业 Wi-Fi 后，SSID/IP 及互联网正常不证明认证服务器实际使用了请求用户名。菜单、主面板顶部与账号／网络行统一灰色信息标记，账号旁标记“未核验”，操作提示仅说明连接流程完成和本次请求账号。网络异常仍优先红色。

点击灰色状态显示“核对连接账号”，列出 Wi-Fi、连接来源、本次请求账号和系统保存账号。系统保存账号只读属性，不额外读取密码；读取失败明确显示未读取到。默认账号不同不触发密码更新，相同也不证明本次会话身份；不会修改系统首选。连接变化后清除证据，并丢弃尚未返回的旧查询结果。应用保留请求目标供后续恢复使用，不把此记录解释为服务端身份。

系统自行恢复时沿用已有系统配置识别和密码核对流程，清除应用请求证据；普通密码网络、热点、开放网络不采用企业身份未核验状态。真实企业身份验收仍依赖服务端记录。控制中心主动断开但未关闭 Wi-Fi 的来源识别尚未解决，应用可能自动恢复。诊断日志新增固定连接阶段，不记录敏感账号或网络数据。

## 0.1.59 补充：应用连接成功状态

企业 Wi-Fi 由应用手动连接或自动重连时，使用所选凭据提交认证，系统调用返回成功并连续确认目标 SSID 和可用 IP；应用最后一次快照仍须有可用 IP。互联网检测通过后，菜单和主面板显示绿色及所选账号。互联网探测未通过时显示红色；认证失败或丢失 IP 不报告连接成功。绿色基于应用连接流程与网络检查，不能独立证明认证服务器实际会话的用户名。

若系统在应用自动重连准备期间已恢复，应用不提交账号认证，转为读取系统配置并核对，不能直接沿用应用最后请求的账号。系统默认账号可能不同于本次应用连接账号，不因此更新密码。系统主动断开但未关闭 Wi-Fi 的来源识别仍是既有限制；0.1.60 起断线通过用户确认处理。

## 0.1.60 历史补充：断线重连由用户确认

下述等待时间在 0.1.63 调整为约 3 秒。

Mac 已连接的记录失联或无可用 IP，等待约 10 秒后仍未恢复时，显示网络和原账号，询问“重新连接”或“取消”。系统的状态通知不包含断开原因，所以手动断开和原因不明的掉线使用同一确认流程，不虚报断线原因。取消不读取密码、保持现状，同一断线期间不重复提示；下一次已连接后再次断线可重新提示。应用启动时若原本已经断线，不主动显示旧会话确认。

确认后再次检查网卡、Wi-Fi 开关、连接、账号及网络变更；系统已恢复或切换、账号变化、休眠或电源关闭时丢弃旧确认。仍断开时，使用原账号执行一次保留系统默认凭据的连接，失败后等待用户操作，不自动连续重试。Wi-Fi 电源关闭再打开时等待系统按自身设置加入。此逻辑不修改系统自动加入、网络优先级或首选账号；窗口中仍保留手动重新连接与切换账号入口。

## 0.1.61 历史补充：账号密码条目名称

自动改名路径已于 0.1.64 移除，以下保留历史行为。

Mac 新增／更新账号密码使用“WiFi Switch 账号密码 · 账号描述 [短标识]”的钥匙串显示名称。标识来自账号 ID 的前 8 位，区分常见重名情形，不使用密码。旧账号及账号描述变化后由独立非交互 helper 尝试仅修改条目名称；按账号 ID 精确匹配，不读取密码、不删除重建、不改变访问控制。失败时保留旧条目，记录固定失败事件和错误码，在成功读取账号密码后再次尝试；首次授权弹窗可能仍显示旧名称。写入新密码但配置提交失败时回滚原密码与原名称。

授权由 macOS 按条目和签名决定；本功能改善可识别性，不承诺取消重复授权。后台静默迁移不扩大钥匙串访问权限，不修改系统 Wi-Fi 的条目。

## 0.1.62 补充：分步授权说明与并发核对

自动核对需要读取系统 Wi-Fi 凭据和 WiFi Switch 账号密码；说明窗口随实际读取步骤更新目标，同时保留账号、网络及可用用户名。系统解锁登录钥匙串及每个条目的访问许可分别由 macOS 决定，不声称可合并为一次授权。

同一连接、账号和来源的重叠静默核对复用一次进行中的任务；连接事件、身份、账号或来源变化使旧任务不再复用，过期结果仍丢弃。发现密码不同仍按原规则再次读取两侧确认稳定，避免误报；取消和授权失败不重复自动请求。无数据迁移，不修改系统 Wi-Fi 凭据和钥匙串访问控制。

## 0.1.63 补充：断线提示与系统加入缓冲

有有效连接记录的网络断开后，默认等待约 3 秒，系统仍未恢复时提示用户选择重连或取消。系统事件合并和五秒后台轮询可能导致实际时长略有差别。系统已加入并获得有效 IP 时取消待执行提示；重新识别账号后仍可显示正常状态。

系统重加入期间，应用不主动发起关联；系统重新加入并获得 IP 后，交互式凭据核对暂缓约 3 秒，让系统操作先完成，静默比较可继续。缓冲结束后正常核对，取消或失败仍按原规则处理。此措施减少潜在授权竞争，不证明系统手动连接卡住的唯一原因，真实设备需复测。无系统 Wi-Fi 设置或凭据变更。

## 0.1.64 补充：启动授权和逐步骤说明

保留启动自动核对。启动、账号刷新和读取成功后均不再自动修改钥匙串条目名称。旧条目保留原名称，账号识别依赖当前授权说明；新建或真正更新密码时继续写入含账号描述的名称。自动核对在每次访问前等待说明完成绘制，并根据实际来源区分登录钥匙串、系统钥匙串管理员授权、普通 Wi-Fi 条目及应用密码。系统与应用密码阶段复用同一说明窗口；等待应用密码授权不会阻塞主界面，过期账号和连接结果被丢弃。

Mac 授权密码由用户在系统窗口输入，应用不获取、保存或代填。许可由 macOS 按条目和应用身份管理。无写入且已经核对相同的本轮操作复用结果，保存后仍必须回读验证，确认不同仍必须稳定二次读取。程序不以缓存伪造一致状态，不承诺不同条目一次授权、跨版本免授权或系统窗口与说明同时出现。手动连接中的系统凭据备份、同步及恢复仍包含独立读写权限；完整重复访问分析见 Mac 0.1.64 验证记录。
