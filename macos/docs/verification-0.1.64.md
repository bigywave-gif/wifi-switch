## 现场证据与原因

只读分析用户截图时间段的统一日志和 `~/Library/Logs/WiFiSwitch/credential-sync.log`，没有读取真实密码或操作授权窗口。

- 14:25:12，主进程 19018 的静默比较返回 unavailable，开始交互核对；原改名 helper 的超时上限为四秒。
- 14:25:33，主进程请求条目授权；14:26:03 用户选择始终允许，随后另一条目仍报告 partition 不匹配并请求授权；14:26:22 完成允许和密码一致核对。
- 授权后至 14:49，0.1.63 日志持续记录后台读取 same/equal。证明当前版本的后续静默访问能复用已获得许可；不能据此推导另一条目或新版也已获许可。

本机安装的 0.1.63 显示 `TeamIdentifier=not set`。Apple Security 的 `partitionIdForProcess` 对未满足 Apple 开发者身份条件的已签名程序回退为代码哈希；现场不匹配日志与这一机制一致。参考：[Apple 源码](https://github.com/apple-oss-distributions/Security/blob/main/securityd/src/clientid.cpp)、[条目授权说明](https://support.apple.com/guide/keychain-access/if-youre-asked-for-access-to-your-keychain-kyca1243/mac)。

## 重复访问逐路径审查

读取调用次数不等于系统要求输入密码的次数。下面的次数是正常分支的代码行为；错误回滚可能增加核对。

| 路径 | 读取或写入行为 | 本次处理与边界 |
| --- | --- | --- |
| 启动／刷新／成功读后改名 | 曾经遍历账号执行条目名称更新，产生独立授权 | 已移除 AppModel 的全部自动调用；新建或真正修改密码时仍写入账号名称 |
| 启动正常核对 | 系统 Wi-Fi 条目与应用账号条目各读取一次 | 两条目仍有独立访问许可；先绘制当前说明再读取，不能用一次允许替另一条目授权 |
| 确认密码不同 | 系统及应用各再次读取，要求身份、来源、值稳定 | 保留，避免把切换过程中的瞬时差异当成真实改密；第二次读取应使用 OS 已授予的许可 |
| 后台轮询 | 同一核对有 30 秒结果缓存，并发请求合并；到期后静默读取 | 已授权版本可正常复用许可；失败不会每轮启动交互授权。连接／账号变更清除旧证据 |
| 手动核对一致且无写入 | 原来应用密码会在比较和操作末尾各读一次 | 已改为本轮只读一次；中间无异步等待或密码写入，不建立跨操作的长期密码缓存 |
| 导入后确认更新 | 同一候选的系统读取结果缓存 30 秒，确认操作复用 | 已有复用机制保留；取消、连接变化及过期清除缓存。实际写入后的独立回读保留，防止保存失败被显示为成功 |
| 显示／隐藏密码 | 首次显示读取；同一编辑窗口已有值时再次显示不重新读取 | 已有界面内复用。保存不同密码时仓库再读取旧值用于变更判断和回滚；不能直接用可能已编辑的输入框值替代旧值 |
| 修改当前账号后重连 | 保存前读旧密码，写新密码；连接入口再读取已保存密码 | 后一读取用于从持久化状态连接，未改为盲用输入框。读权限与写权限可能不同，尚无现场证据证明这一路每次重复弹窗 |
| 连接但不覆盖系统首选 | 连接前备份 user/system 两域，连接后读取检查；若 native association 改写，仅恢复本次改写并回读 | 保留，否则无法证明系统原凭据未被覆盖。system 域可能要求独立管理员授权；此路径不能声称一次授权全覆盖 |
| 同步系统首选账号 | 读取 user/system，按实际差异写入，然后回读；失败时按变更恢复 | 保留事务验证。不同条目／域／读写操作可能分别授权；本次未重构此权限与连接流程 |

## 自动化验证

277 项 Swift 测试／21 个 suite 通过（最终运行约 3.288 秒）。新增或强化验证：

- 说明准备发生在每一次用户域、系统域及普通 Wi-Fi 凭据读取之前；准备失败停止下一次读取，读取成功不多查其他域。
- 授权等待期间显示当前账号、用户名、网络、目标类型；主 actor 可继续处理状态，重复刷新不发起第二轮读取。
- 系统域显示管理员用户名及密码说明，登录钥匙串显示钥匙串密码说明。
- 账号变化丢弃悬挂读取；拒绝不循环；未写入的一致核对只读取一次应用密码。
- 稳定差异二次检查、写后回读失败、导入缓存失效、持久化失败回滚等已有测试通过。
- 隔离临时钥匙串内使用合成密码验证异步读取及条目不存在的返回值，没有读取真实用户凭据。

测试日志：`.build/startup-authorization-tests.log`。默认脚本首先遇到既有缓存路径不匹配，随后使用 `.build/startup-authorization` 独立缓存完成测试，没有删除原缓存。

## 原生窗口验证

使用生产 `CredentialAccessContext.swift` 和演示账号构建隔离预览，无 Security/CoreWLAN 调用。CUA 截图及可访问性树确认系统登录钥匙串阶段和应用账号密码阶段完整可见，账号、可能的条目名称及输入密码类型相互对应。同一个 panel 在两阶段保持可见，窗口编号相同；日志：`.build/startup-authorization/preview-native.log`。

说明采用原生可选择文本；调用读取前完成布局、显示并让主队列继续一轮，读取期间不会切到下一阶段。macOS 自己的授权窗受系统调度、遮挡和其他程序影响，应用不能保证同一时刻弹出。预览没有伪造系统授权框，不能替代真实重装验收。

## 交付边界

保留启动自动核对。没有收集或代填 Mac 登录／管理员密码，没有调整钥匙串 ACL，没有迁移密码存储格式，没有改变系统 Wi-Fi 配置。旧条目的通用名称继续保留，说明中标明它对应当前账号。系统授权失败不伪造核对成功。

本次修复启动核对的多余改名授权、说明时序与分来源内容，并去掉无写入手动核对的冗余读取。尚未保证所有账号、不同权限域、读写操作或升级后只授权一次；连接／编辑／删除等其他入口没有全部纳入本次说明窗协调器。真实旧条目上的完整授权次数仍需安装后由用户验收。新包不自动安装，Windows 无变更。
