# 0.1.48 / build 49 验证

日期：2026-10-22。

## 问题与实现

用户截图显示 macOS 请求管理员名称及密码以允许 WiFi Switch 使用系统钥匙串。上一版 `SystemConnectionReader.readCredentials` 遍历用户域与系统域，用户域成功后仍继续读取系统域。这是可以导致多余管理员授权的明确代码路径；截图不能证明当次用户域读取是否已经成功。

本版对企业认证及普通网络的 CoreWLAN 后备读取实行用户域优先、仅不存在时后备系统域：

- 完整用户凭据：直接返回，不调用系统域读取。
- 用户条目不存在：继续系统域一次。
- 任一来源发生取消、拒绝、禁止交互或接口错误：保留阶段和返回码并停止。
- 读取成功但用户名／密码不完整：报告缺失，不用另一域覆盖。
- 开放网络不读密码；认证类型未知时停止。

添加／更新和非交互比较使用同一函数。生产 `CoreWLANDefaultStore.read` 仅在 `errSecItemNotFound` 时返回 nil；其他错误抛出，所以错误不会被当作不存在而触发下一次授权。个人热点标准 AirPort 条目的精确引用读取保持不变，多个标准条目冲突仍拒绝导入。系统默认账号写入、保留及恢复逻辑未修改。

这是一项明确的应用读取策略，不声称用户钥匙串记录能证明服务器接受的实时身份。已有账号更新仍验证用户名、SSID 和认证类型；身份变化或冲突不覆盖目标账号。代码不设置钥匙串 ACL、不保存管理员密码、不生成系统授权按钮。

API 参数与返回码依据 [Apple CoreWLAN 文档](https://developer.apple.com/documentation/corewlan/corewlan-functions) 和本机 CoreWLANUtil.h；[Apple 钥匙串授权说明](https://support.apple.com/guide/keychain-access/kyca1243/mac) 描述具体条目访问的“始终允许”，不能把它等同于所有管理员授权。
