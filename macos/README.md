# WiFi Switch

面向使用者的功能与操作说明见 [使用说明](Resources/UserGuide.txt)。应用“使用说明”入口和安装包均使用这份独立指南；本 README 保留安装、开发及维护资料。

每个版本的新增、BUG 修复、调整和验证限制见 [完整版本记录](CHANGELOG.md)。后续新包将随安装磁盘及应用资源目录提供 `CHANGELOG.txt`；已发布旧包不改写。

macOS 原生菜单栏工具，按“账号 → Wi-Fi”管理企业 Wi-Fi（802.1X）、普通密码 Wi-Fi／手机热点和开放网络。一个账号可以关联多个 Wi-Fi，共用一份凭据；同一 Wi-Fi 也可以关联多个账号。展开账号后点击目标 Wi-Fi 旁的“连接”。支持添加、修改和删除账号，密码保存在本机系统钥匙串。

## 内部版安装（无需开发者会员）

本次内部包为 **0.1.68，Apple Silicon（M 系列芯片 / arm64），macOS 13 或更高版本**。Intel Mac 请勿使用此包，需要另行构建对应架构版本。安装者不需要开发者账号、Xcode 或签名证书。

0.1.68 起使用不含个人命名的应用标识。账号配置目录保持不变；已有密码通过账号 UUID 和旧条目属性识别，继续在原钥匙串条目中使用，不导出、不批量复制。出现多个候选或授权失败时提示失败。系统可能重新请求定位或钥匙串授权，部分界面偏好会恢复默认。公开说明、界面示例与测试数据均使用虚构名称。

1. 打开 `WiFi-Switch-0.1.68-arm64-internal.dmg`，将 **WiFi Switch.app** 拖入旁边的 **Applications（应用程序）** 文件夹。升级时先从旧应用菜单栏标题右侧齿轮选择“退出系统”，再替换应用。
2. 从“应用程序”打开 WiFi Switch，不要直接在安装磁盘内长期运行。可将同目录的 `使用说明.txt` 复制到本机保留，然后推出安装磁盘。
3. 此内部版采用本地证书签名，**没有 Apple 公证**。首次打开若提示开发者无法验证，在确认包来自可信内部渠道后，进入 **系统设置 → 隐私与安全性 → 安全性 → 仍要打开**，按系统提示确认。只授权此应用，无需关闭系统安全保护。公司设备若受管理策略限制，请联系管理员。操作依据：[Apple 官方打开说明](https://support.apple.com/zh-cn/102445)。
4. 首次启动可按下文添加账号和关联 Wi-Fi；菜单栏会出现一个紧凑的圆圈双向箭头图标。退出应用不会主动断开系统 Wi-Fi；重新打开时正常连接只恢复标记，网络异常才按下文规则尝试恢复。

安装包只包含应用、使用说明、相关说明文档和 Applications 快捷入口，不包含开发者签名私钥或任何个人 Wi-Fi 账号。账号和密码由各位使用者在自己的 Mac 上添加。

## 账号密码条目名称

WiFi Switch 的账号密码条目使用“WiFi Switch 账号密码 · 账号描述 [短标识]”作为名称，例如“WiFi Switch 账号密码 · 办公账号 [A1B2C3D4]”。不同描述便于在钥匙串授权提示中识别，短标识用于区分重名账号；不会显示密码。新增账号或明确保存不同密码时使用该名称；只改账号描述不会为同步条目名称访问钥匙串。

0.1.64 起取消启动、刷新和成功读取后的自动改名。现场日志证实旧版的后台改名也可能触发系统授权，因此不能依赖“非交互”设置保证它不弹窗。旧条目可能仍显示“WiFi Switch 账号密码”；自动核对的授权说明会明确列出当前账号备注、用户名、Wi-Fi 和正在读取的凭据类型。说明先完成绘制再发起读取，系统与应用密码切换时在同一窗口更新，核对结束后关闭。macOS 控制系统弹窗的时机，不能保证两个窗口同时出现，也不能合并钥匙串解锁和不同条目的必要授权。

## 系统提示如何处理

- **首次打开授权**：确认是否允许打开这个内部应用；按上面的安装步骤处理。
- **“WiFi Switch 想要使用钥匙串中的机密信息”**：这里要求的是“登录”钥匙串密码，通常是 **Mac 登录密码，不是 Wi-Fi 密码**。确认应用与条目名称正确后输入并选“始终允许”。每个账号的密码是独立条目，可能分别授权；权限保存在这台 Mac 当前用户的钥匙串中。开发者统一签名打包，安装机器不会自动生成签名证书。
- **“想要使用系统钥匙串，输入管理员名称和密码”**：这是 macOS 管理员授权，填写这台 Mac 的管理员用户名和对应登录密码。与访问具体密码条目的“始终允许”窗口不同，按钮由系统决定。0.1.48 起，企业凭据及 CoreWLAN 后备查询在用户钥匙串读到完整凭据后立即结束，不再额外读取系统钥匙串；只有用户条目不存在时才继续。必要的系统授权仍保留。
- **“输入网络的名称和密码”**：这是 Wi-Fi 认证窗口。即使已保存密码，账号密码不正确、认证服务器或公司网络策略也可能导致此窗口。检查应用中保存的账号信息；如在系统窗口改了密码，菜单栏可提示核对并更新应用保存的密码，详见下文。证书信任提示应按公司 IT 提供的信息核对。

“始终允许”不等于所有情况永不提示：本次已验证临时凭据在同版本重复读取、进程重开时可以复用；**本地签名的应用更新后仍可能需要重新授权**，钥匙串锁定或权限被重置时也可能提示。尚未完成另一台 Mac 的首次安装以及旧真实密码条目手动授权验收，不能把允许安装当作钥匙串永久授权保证。详见 [签名与验证说明](docs/signing.md)。

## 打开与使用

### 查看版本与使用说明

从 macOS 顶部 **WiFi Switch → 关于 WiFi Switch**，或应用菜单栏面板的 **齿轮 → 关于 WiFi Switch**，打开系统原生“关于”窗口，查看应用图标、名称、版本号、括号中的构建号、芯片架构、最低系统要求和发布类型。版本与构建号读取正在运行的应用包，不依赖网络。

从顶部 **帮助 → WiFi Switch 使用说明**，或 **齿轮 → 使用说明**，打开应用内的 `UserGuide.txt`。它只介绍当前功能与使用方法，推出安装磁盘后仍可阅读；版本变更单独保存在 `CHANGELOG.txt`。

### 连接与账号管理

构建后的应用：`dist/WiFi Switch.app`。双击打开后，菜单栏只显示 16 点的圆圈双向箭头图标，不占用应用名称的文字宽度；悬停可查看“WiFi Switch”。关闭管理窗口不会退出应用，点击菜单栏图标仍可切换账号；面板标题右侧的齿轮菜单分为三组：“关于 WiFi Switch”；“配置管理、使用说明”；“退出系统”，组间以分隔线隔开。“配置管理”打开账号管理窗口，“退出系统”退出 WiFi Switch；连接进行中暂不可退出。底部不再重复显示这两个入口。菜单栏顶部独立显示当前已连接的 Wi-Fi 与已识别账号：互联网检测通过后，绿色对钩表示已登记且凭据已确认一致的账号，黄色叹号表示未知账号或已确认密码不同，点击可添加配置或更新密码；没有本次连接的一致证据且自动核对失败时显示可点击的灰色信息标记，点击打开“核对账户信息”；断开、关闭 Wi-Fi、持续无地址或互联网检测失败显示红色叉号。等待 IP、读取名称受限等状态另行提示，不冒充已连接或已断线。下方“其他网络”每次打开默认收起，点击展开后显示已保存的 Wi-Fi 与账号组合，并可点击连接；每行左侧使用灰色 Wi-Fi 图标，与顶部已连接网络的蓝色图标区分。当前连接组合不重复展示，但同一 Wi-Fi 的其他账号、当前账号关联的其他 Wi-Fi 仍可选择。菜单栏不再显示底部操作结果文字，连接进度与认证等待提示保留；列表过长可滚动。菜单栏宽度仍约 233 点，展开状态独立于配置管理窗口。齿轮菜单不再提供“添加当前 Wi-Fi 配置”。较长名称省略显示，悬停可查看完整名称。

1. 点击 **添加账号**。备注和关联 Wi-Fi 为选填；用户名、密码的必填标识随勾选的网络自动更新，具体规则见下表。必填项未填写时，“保存”按钮旁会提示具体缺少什么；扫描网络、连接账号或确认连接状态期间，也会显示暂不能保存的原因。“关联 Wi-Fi”会在已获定位授权时自动扫描，将已保存和附近网络合并成可滚动的多选列表；可点击 **扫描附近 Wi-Fi** 刷新，同时勾选企业 Wi-Fi、普通 Wi-Fi 或手机热点，也可手动输入准确名称并点击 **添加**。已选网络不会因重新扫描或暂时不在附近而丢失。点击 **保存** 时才统一保存账号与所选关联；取消不会创建账号、网络或密码。也可以不选网络，稍后添加。保存不会连接网络，也不会验证密码。
2. 展开账号，点击 **添加 Wi-Fi**。扫描列表显示所有可识别名称的 Wi-Fi，按信号强度排序，同名网络合并显示；分别标注“企业认证”“Wi-Fi 密码”“开放网络 · 无密码”或“连接时识别”。普通 Wi-Fi 和手机热点可以正常选择。也可以手动填写准确的 SSID；名称区分大小写，空格会保留。关联受密码保护的网络时若此账号缺少所需凭据，先通过 **修改账号** 补充并勾选网络后保存。添加关联不会改变现有连接。
3. macOS 要求定位权限才能向应用提供 Wi-Fi 名称。点击 **允许定位**，在系统弹窗中授权。拒绝过权限时，可以点击 **前往设置**，在“隐私与安全性 → 定位服务”中开启 WiFi Switch。
4. 点击该账号下目标 Wi-Fi 旁的 **连接**，先选择是否同步为此 Wi-Fi 的系统首选账号（见下文）；取消则不连接。应用先找到目标网络，重新检查实际认证方式及所需凭据，再断开当前连接进行认证，最后确认目标 SSID 和可用 IP 地址。企业网络使用用户名和密码；普通密码网络只使用密码，开放网络不提交账号密码。认证方式无法识别、同名网络存在不同认证方式，或缺少所需凭据时，会在主动断开现有连接前报错。切换会短暂断网。
5. 账号标题右侧的 **… → 修改账号** 可以编辑备注、用户名、密码和 Wi-Fi 关联；编辑时用户名是否必填同样随所选网络变化；已有保存密码时可留空保留，原先没有密码的开放网络账号新增受密码保护的关联时需补填密码。与新建账号一样，可以扫描、多选或手动添加网络。修改用户名或密码会对这个账号关联的所有 Wi-Fi 生效。点击密码右侧的 **眼睛图标** 可查看已保存的密码（或当前输入的新密码），再次点击隐藏；密码留空保留原密码。点击 **保存** 生效，取消不保存。关闭编辑窗口或切到其他应用后会隐藏明文。
6. Wi-Fi 行右侧 **… → 移除 Wi-Fi** 只移除该账号与此网络的关联，保留账号、密码和其他关联，不主动断开系统连接。账号标题的 **… → 删除账号** 会在确认后删除整个账号、它的所有关联及钥匙串密码，不影响其他账号。

**修改当前账号后自动重连**：当前账号的用户名或密码发生变化时，点击“保存”会先保存新信息，再询问是否同步系统首选账号，然后用新凭据重新认证原先使用的那一个 Wi-Fi（取消询问不会撤销已保存的账号修改），可能短暂断网。编辑窗口会提前显示目标网络。一个账号关联多个 Wi-Fi 时，不会逐个连接。只改备注或关联、密码留空或原样保存、编辑其他账号、新建账号时不会自动切换网络；已切到其他网络、关闭 Wi-Fi 或移除原网络关联时也不会强行重连。保存失败不会发起连接；保存成功但认证失败时保留新信息，显示明确错误并提供修改入口。修正连续重连失败账号的凭据后保存，可重新发起认证。

新建账号的必填规则（混选时按所选网络中要求最多的情况处理）：

| 所选 Wi-Fi | 用户名 | 密码 |
| --- | --- | --- |
| 包含企业 Wi-Fi | 必填 | 必填 |
| 普通密码 Wi-Fi／热点，可混选开放网络 | 选填，不用于普通网络连接 | 必填 |
| 仅开放网络 | 选填，无需提供 | 选填，无需提供 |
| 尚未选择网络或认证方式待识别 | 选填 | 必填；连接前再次核对认证方式 |

同一个账号下共用一份密码，密码不同的网络请分别创建账号。只关联开放网络且不填密码时，不创建密码条目，也不会读取钥匙串密码。手动添加、尚未扫描到的网络暂按“连接时识别”处理；如果实际是企业网络，会要求补充用户名后再连接。

主窗口顶部状态栏左侧显示连接状态、Wi-Fi 名称和当前账号备注，右侧仅显示已保存账号总数；同一个账号关联多个 Wi-Fi 仍只计一个账号。未识别账号时明确提示，不显示登录用户名。连接状态自动刷新。

配置管理窗口中，当前连接正常的账号与 Wi-Fi 条目使用蓝色 Wi-Fi 图标，其他条目使用灰色图标；颜色跟随连接状态更新。配置管理窗口按账号分组，当前连接正常的账号自动置顶，标题右侧使用与菜单相同的核对状态；确认一致且联网正常显示绿色圆圈、黑色对钩，与下方“连接”按钮和状态点居中对齐；其他账号保持原来的相对顺序，不改写保存顺序。切换成功后对钩和置顶随当前账号更新，连接尚未确认或异常时不显示当前账号对钩；重开应用核对连接后恢复。管理窗口标题显示账号备注和关联 Wi-Fi 数量；展开后每个 Wi-Fi 占一行。菜单栏按上文的“当前连接 / 其他网络”显示。右侧同一列居中对齐连接状态点或“连接”按钮。状态按“账号 + Wi-Fi”组合区分：当前组合显示状态点，同一账号下的其他 Wi-Fi 仍可点击“连接”。状态点以柔和光晕闪动：绿色要求当前账号已确认且互联网检测通过；核对不可用为灰色、密码不同为黄色、网络异常为红色，与菜单一致。点击红点查看具体原因，再按需点击“重新连接”；查看原因不会触发重连。未识别账号时不显示绿色；互联网状态按菜单的 TLS 探测结果展示，不代表所有公司业务服务可用。开启系统“减少动态效果”后光点静止。

主窗口保留“正在连接”、连接成功、失败及异常提示区域；菜单栏保留连接进度，不重复展示底部操作结果文字。Wi-Fi 行右侧“⋯”菜单提供 **查看 Wi-Fi 信息**、**重新连接** 和 **移除 Wi-Fi**。点击“重新连接”会使用该账号保存的凭据重新认证，包括当前已连接的账号；会短暂断网。只展开菜单不会触发连接。账号列表、当前账号和成功提示只显示账号备注（如“办公账号”“项目账号”）；备注为空时显示“未命名账号”。用户名仍可在账号编辑窗口查看和修改。连接进行中会锁定重复连接和账号编辑，避免多个操作互相覆盖。

企业 Wi-Fi 由应用手动连接或用户确认重连时，提交所选账号凭据，系统连接调用成功并连续确认目标 Wi-Fi 和可用 IP 后，互联网检测通过显示绿色。若系统自行恢复，按系统保存配置重新识别账号。系统保存账号可以与应用本次请求账号不同，不因此提示修改密码。绿色表示应用连接流程及网络检查通过；它不等同于查询认证服务器的当前会话身份。网络异常优先显示红色。

### 查看 Wi-Fi 信息

在配置管理窗口展开当前已连接账号，选择当前 Wi-Fi 行右侧 **… → 查看 Wi-Fi 信息**。仅已确认连接的账号与 Wi-Fi 组合显示此入口；其他账号（即使关联相同 SSID）、其他网络和未识别账号均不显示。窗口展示当前网络的 IPv4 地址、子网掩码、IPv4 网关、IPv6 地址及前缀、IPv6 网关、当前 DNS（Wi-Fi）、手动 DNS、自动 DNS、当前接口 MAC、接入点 BSSID、信道、信号与噪声、协商速率，以及系统返回的安全类型和认证方式。文字可选中复制；每 5 秒更新，也可手动刷新。

窗口按当前连接标记校验账号，并读取对应 Wi-Fi 的实时网络信息。切换账号、断开网络、Wi-Fi 关闭或无法确认当前网络时，清除信息并自动关闭窗口，不再展示保存配置或其他网络的信息。DNS 分三行展示：“当前 DNS（Wi-Fi）”读取系统为当前 Wi-Fi 接口配置的解析器地址；“DNS（手动设置）”读取已应用的手动配置；“DNS（自动获取）”显示网络提供的地址。当前解析器无法确认时显示“未确认”，不按手动设置猜测；多地址按系统顺序列出，不代表每次查询都会使用全部地址。请先在系统设置中点击“好”保存修改，再刷新。VPN、加密 DNS 或按域名分流可能使用其他解析器；两组配置来源同时展示不表示同时生效。系统未返回的字段显示“未获取”；802.1X 的具体 EAP 类型及本次认证用户名无法由此接口确认，不猜测，也不读取密码。查看信息不会连接或修改网络。

## 当前账号显示

主窗口和菜单栏共用同一份连接状态；点击 Wi-Fi 行状态点查看连接详情。账号标记由连接结果自动管理，更多菜单不再提供手动标记或清除标记操作：

- **当前账号：账号备注**：应用使用所选账号提交凭据，连接调用成功且目标 Wi-Fi 与 IP 连续确认后显示当前账号。互联网检测通过时主窗口和菜单栏显示绿色。系统保存的默认用户名可能不同，系统“拷贝用户名”显示保存值，并不能单独证明本次服务器会话的身份。
- **当前账号：未识别**：没有能与当前网络匹配的保存记录。系统已有连接仍可继续使用；可选择添加系统配置或手动连接。后台不会靠密码猜测账号身份；仅对已唯一匹配的账号核对密码是否一致。
- **当前账号（手动标记）**：仅用于兼容旧版本留下的记录；不等同于系统核实身份。通过工具重新连接成功后，会改为本次连接确认的账号记录。

连接成功后，账号标记与成功时间一起保存到本机配置文件。**版本更新、退出重开、系统重启、休眠和唤醒均保留这份记录**。恢复时读取当前网络及系统保存的用户名；能唯一匹配时更新标记，否则显示未知账号。恢复标记不重新认证、不触发断网；已识别账号还会进行下述静默密码核对。启动或唤醒时网卡暂不可用、读不到名称、定位权限不足时，保留记录并等待后续状态核对。

网络状态变化只影响实时状态，不删除保存的账号记录：断网、关闭 Wi-Fi 或暂时处于其他网络时，不把旧账号显示为当前正常连接；回到对应 Wi-Fi 后重新匹配系统保存的信息，能唯一识别时恢复显示。用户主动连接或重新连接时重新建立连接记录：认证开始前使旧标记失效，成功后保存所选账号，失败后不会把旧账号误标为已连接。删除账号、修改用户名或密码、移除当前 Wi-Fi 关联也会使不再有效的记录失效；只修改备注或其他 Wi-Fi 关联保留记录。没有当前账号标记不代表系统没有登录。

首次从 0.1.7 及更早版本升级时，如果当前 Wi-Fi 下存在唯一的最近成功账号，会一次性迁移该记录；日期相同而无法区分时不猜测。本版本配置格式升级为第 4 版，继续读取第 1、2、3 版配置。

### 断线后重新连接

应用每 5 秒检查 Wi-Fi 连接和 IP 地址。已连接网络断开或未取得可用 IP 时，通常等待约 3 秒；若系统未自行恢复，应用弹出“Wi-Fi 连接已断开”，显示上次使用的 Wi-Fi 和账号，请用户选择“重新连接”或“取消”。macOS 的连接通知不提供断开来源，因此手动断开和原因不明的掉线都可能出现此提示，不能据此断言发生了网络故障。

- 系统 Wi-Fi 自行加入并取得 IP 后，WiFi Switch 会给系统连接约 3 秒缓冲，再执行可能弹授权的账号核对；静默检查和取消旧重连提示仍可进行。系统事件或后台轮询时间可能使提示稍有延迟。
- 点击 **取消** 后保持现状，同一次断线不会反复询问或读取账号密码。需要时，可在账号对应的 Wi-Fi 状态详情中点击 **重新连接**，或者选择其他账号的 **连接**。退出应用后处于断线状态时不会主动询问。
- 点击 **重新连接** 后，应用重新核对当前网络和账号；若系统已恢复、已切换到其他 Wi-Fi、Wi-Fi 已关闭或账号已变化，则不执行旧请求。仍符合条件时使用原账号执行一次连接，保留系统首选凭据；失败后显示原因，等待用户处理，不进行连续自动重试。
- 用户关闭再打开系统 Wi-Fi 时，等待系统按自身配置加入，应用不抢占。系统自动加入设置、首选网络顺序与 Wi-Fi 开关由 macOS 保持原有机制。系统自行恢复时不提交应用账号，重新识别系统配置。
- 账号保存或认证所需的钥匙串授权与证书提示仍由 macOS 决定。单个网站、VPN 或业务服务故障不触发重新连接确认。

账号标记优先使用本次应用连接记录；系统自动加入后按下文的系统保存信息重新识别。无法唯一匹配时显示未知账号，不为了识别而重新连接。

## 支持范围与连接状态

- macOS 13 或更高版本；使用 SwiftUI、CoreWLAN、Security 与 CoreLocation，无第三方运行时。
- 支持以用户名和密码登录的企业 Wi-Fi、普通共享密码 Wi-Fi／手机热点，以及开放网络。连接后还需网页认证的 Portal 不会自动登录，必须提供客户端证书的 EAP-TLS 仍不支持。普通网络使用 [Apple CoreWLAN 的密码连接接口](https://developer.apple.com/documentation/corewlan/cwinterface/associate%28to%3Apassword%3A%29)。
- 首次认证可能出现 macOS 的证书信任或管理员授权窗口，仍需用户处理。应用不会绕过证书校验。
- 不自动删除系统已保存网络或修改公司管理的网络配置。某些 MDM/EAP 配置可能限制账号覆盖，需在实际目标网络验证。
- 成功条件是 CoreWLAN 连接调用成功，且连续三次检查确认目标 SSID 与可用 IP；这不等于已测试互联网或内部业务系统可用。 菜单栏另执行下述互联网检测，结果独立于连接成功通知。
- “已连接”标记属于 Wi-Fi。账号标记来源于本应用的连接或手动记录，恢复时会核对当前 Wi-Fi；现用 CoreWLAN 公开接口没有实时认证用户名读取方法，钥匙串查询返回的是保存值，恢复记录不等同于实时核实系统认证身份。参考：[Apple CoreWLAN](https://developer.apple.com/documentation/corewlan)、[钥匙串账号查询](https://developer.apple.com/documentation/corewlan/corewlan-functions)。
- CoreWLAN 认证调用由系统同步处理，运行在专用后台队列，不阻塞界面；系统弹窗可能延长认证时间。调用返回后，连接验证最多持续约 30 秒。
- 切换失败不会删除已保存的账号。必要时点击原账号重新连接。
- 保存凭据不代表服务器已认可该账号。认证阶段再次弹出用户名/密码框，可能是服务器拒绝了已提交的凭据；需要结合认证结果判断，不能仅凭弹窗推断“密码没有保存”。应用会将 EAPOL 错误显示为中文，并提供修改账号入口。
- 如果在系统弹窗中重新输入了不同的正确密码，请同步修改本应用中的账号密码；系统弹窗不会自动回写本应用的独立账号条目。

## 系统识别、确认导入与首选账号（0.1.34）

### 系统自动加入后的账号标记

系统网络变化、唤醒、重开应用后，读取当前 SSID，并尝试在不弹授权窗口、不读取密码的条件下读取系统保存的企业用户名。以 **SSID + 用户名 + 认证类型** 唯一匹配已保存账号，匹配成功自动更新标记并置顶，不要求再次连接。普通 Wi-Fi／热点没有企业用户名，只在该网络唯一关联一个账号时按网络关联识别；存在多个候选、读取被拒绝、凭据缺失或两个钥匙串域信息冲突时，显示未知账号，不猜测。

标记悬停会注明“根据系统保存配置识别”。**系统保存的首选用户名不是本次 EAP 认证实际身份的证明。** WiFi Switch 本次主动连接成功时优先保留本次账号；检测到系统连接变化后才重新识别。选择不同步后，应用退出重开时，系统保存账号也可能与尚未中断的实际会话不同，不能仅靠保存值确认实际权限。应以网络认证端信息核实；应用不读取私有实时认证接口，不使用 IP 地址猜账号。

后台用户名查询在独立短进程中关闭钥匙串交互，通过 Security 框架仅查询条目属性，并核对精确 SSID 和系统 EAP 服务名称，从账号属性获取保存的用户名，不请求密码数据。查询覆盖默认、数据保护和系统钥匙串；读取失败或多个条目用户名冲突时返回未知，4 秒未返回也按未知处理。主应用提供已识别的 SSID，并在查询后再次核对连接；辅助进程无法单独读取 SSID 时不会提前跳过用户名查询。不会更改主应用的钥匙串交互设置。本机已只读验证可以识别系统保存的 Example-Enterprise 用户名并唯一匹配已有账号；其他 macOS 版本、管理策略或钥匙串配置仍可能使读取不可用。

### 添加系统已连接的配置

当前已连接且具有可用 IP，只有成功读取系统身份、并确认本应用没有对应配置时，才自动提示添加配置。读取失败、无法确认用户名、认证类型冲突或多个候选无法区分时，不自动弹出新增窗口；仍可手动选择添加。已有账号唯一匹配时直接更新标记，并关闭之前尚未确认的自动新增提示。菜单栏未知账号旁的 **黄色叹号** 可手动打开添加窗口。填写必填的 **Wi-Fi 描述** 并点 **添加** 后，自动读取系统保存的用户名、密码及 Wi-Fi 名称，描述作为新增账号的名称；保存回读校验完成且互联网检测通过后显示绿色对钩。普通 Wi-Fi 仅导入密码，开放网络无需密码。macOS 可能要求钥匙串访问授权。

- 点击 **取消** 或关闭窗口不会新增配置，当前连接仍显示黄色叹号，同一 SSID 不再自动打扰；可点击菜单栏黄色叹号或主窗口“添加此配置”重新打开。
- 新配置的密码在确认后读取；已有账号可以进行下述自动核对。保存不发起连接，不修改系统首选顺序或自动加入设置。
- 普通密码 Wi-Fi 和个人热点导入时，先按准确 Wi-Fi 名称查找系统标准 Wi-Fi 密码条目，再逐项读取密码；没有标准条目时才尝试 CoreWLAN。授权取消或被拒后停止，不反复换接口请求。认证方式无法确认、凭据缺失、访问失败分别说明原因，接口错误保留阶段与系统错误码。多个条目的密码不一致时不猜选。系统设置能拷贝密码，并不代表本应用无需钥匙串授权。
- 企业凭据及 CoreWLAN 后备查询按用户域优先、系统域后备读取：成功取得完整凭据即结束，只有未找到条目才切换来源；读取失败、取消／拒绝授权或内容不完整均停止。不再为了比较两个域而额外读取系统域密码。普通 Wi-Fi 标准条目读取中若存在不同密码仍报告冲突；更新已有账号时继续核对目标用户名、SSID 和认证类型。
- 网络改变、导入途中取消或保存失败时，不把结果写到其他网络。已有相同配置会复用；不会静默覆盖已有账号名称或密码。
- 密码仅进入本机应用专用钥匙串条目，不进入 JSON、日志或命令行。取消后已发出的系统授权查询可能仍需用户在系统窗口中取消，其返回结果会被丢弃。

### 系统密码变化与已有账号补关联

系统自动或手动连接后，菜单栏按以下分支处理：

| 系统配置与应用的关系 | 状态与点击后的操作 |
| --- | --- |
| 账号和 Wi-Fi 关联已存在，密码不同 | 提示更新已有账号；点“更新”才保存新密码，保留名称、用户名和全部关联 |
| 企业账号已存在，Wi-Fi 尚未关联 | 展示唯一匹配的已有账号；点“添加”将 Wi-Fi 关联到该账号，不重复新建账号 |
| 账号及其关联都不存在 | 输入 Wi-Fi 描述，点“添加”新建账号并关联当前 Wi-Fi |
| 已识别账号，但不能静默核对密码 | 启动及系统回切时自动核对，已有授权由系统复用，必要时请求授权；取消或失败后为灰色，可点击重试，不误报密码不同 |

企业账号先按当前 SSID、认证类型和用户名匹配，缺少关联时再按全体账号的用户名唯一匹配。存在多个候选时停止，不任意选一个。普通 Wi-Fi／热点没有用户名，仅能按已有关联唯一匹配；不同热点即使密码相同，也不据此合并账号。

已唯一匹配的账号先在禁止交互的独立辅助进程中比较密码（4 秒上限、30 秒缓存）。0.1.56 起，启动及系统回切后若静默读取受限、没有本次连接的一致证据，会自动通过与导入相同的读取路径核对；已有许可由系统复用，确需许可时由 macOS 请求授权。无需再点击核对。无当前连接的一致证据时仅保留无法核对状态，不伪称密码不同。添加／更新已完成保存回读校验的，同一次连接继续保留该一致证据，后续静默读取失败不会再要求手动核对。后台继续检查真实差异，断开、换网、连接事件、休眠或账号改变使证据失效并重新核对；不会持久保存密码摘要。仅本次连接的应用会话仍保留所选账号，不拿系统原默认凭据误判密码过期。

从 0.1.50 起，添加／更新完成后先回读应用保存的密码，一致才显示成功。后续比较会检查本次导入的凭据来源（标准个人网络条目、用户域、系统域）；来源变了按不可用处理，不直接判定密码变化。比较发现不同时再次读取两边，只有身份、来源及两份密码均稳定仍不同才提示更新；读取途中变化按不可用处理。来源记录仅用于本次运行和当前连接范围，不写入账号配置。

若更新后仍提示不一致，可查看 `~/Library/Logs/WiFiSwitch/credential-sync.log`。记录包含版本、时间、阶段、比较结果、来源类别和错误码，帮助区分保存回读失败、来源变化、读取中变化、持续不一致及辅助进程失败。**不记录 SSID、用户名、账号 ID、密码或密码摘要**，仅本机保存、限长轮换，不上传。日志不能证明认证服务器实际接受了哪个凭据，也不会更改系统钥匙串权限。

补关联时如果又发现密码不同，会先展示已有账号和影响范围，再由用户点击“添加并更新”。该账号的所有 Wi-Fi 共用一份密码；新关联和密码一起保存，失败时回滚。取消不写入，成功后显示绿色对钩。已确认密码过期的账号在本次应用运行中不会自动用旧密码重试；更新成功或用户手动连接成功后恢复。这里只核对系统保存配置，不保证取得认证服务器实际接受的实时身份。

### 连接前选择是否同步系统首选账号

每次主动“连接”或“重新连接”，以及修改当前账号凭据后触发的重连，先询问：**同步为系统首选账号？** 弹窗仅显示 Wi-Fi 和账号名称；点击蓝色问号“设置说明”，可查看两个选项的区别及其对系统设置的影响。

- **同步账号**：连接调用成功且连续三次确认目标 SSID 和可用 IP 后，同步该 Wi-Fi 的系统保存用户名、密码；普通网络只同步密码，开放网络不写密码。
- **仅本次连接**：使用所选账号完成本次连接，保留该 Wi-Fi 原有系统账号。连接前暂存原凭据；若系统关联过程自行改写了它们，结束时恢复并读回核对。无法读取原凭据时先停止，不冒险断网覆盖；检测到其他程序并发改写时不覆盖第三方结果，并明确报错。
- **取消**：不发起连接，不读取连接密码，也不清除原连接记录。

自动恢复不弹此选择，保留原有系统凭据。两种选择都不主动调整系统网络顺序、“自动加入”或其他网络配置；公司网络与家中热点各自保留凭据。macOS 自己可能根据连接行为更新偏好，本应用不锁定首选网络。0.1.31 曾修改的顺序没有原始备份，升级不会猜测重排恢复。

同步使用公开 CoreWLAN 接口；更新用户域，只有已有系统域凭据时才更新系统域。保存失败显示明确错误并尝试回滚，不当作密码认证失败。同步和保留原凭据都可能要求钥匙串授权。此前系统 Wi-Fi 首次重连读取 Example-Enterprise 时弹登录钥匙串授权的问题，本版不宣称已消除。

参考：[Apple CoreWLAN 接口](https://developer.apple.com/documentation/corewlan/corewlan-functions)、[系统自动加入规则](https://support.apple.com/en-ae/102169)。

## 数据与密码

- 升级到本版本时，原有“Wi-Fi 下的账号”自动迁移为“账号下的 Wi-Fi”。保留账号 UUID、备注、用户名、使用时间、原 Wi-Fi 关联和当前账号记录；迁移不读取、不改写钥匙串密码，也不触发网络连接。第 4 版增加网络认证类型和是否已保存密码的标记，原有企业账号按已有密码保留。旧格式原文件会先备份为同目录的 `accounts-pre-v4-<UUID>.json`，权限同为 `0600`。
- 不按相同用户名自动合并旧账号，避免合并密码不同的记录；每个原账号独立保留。可以在账号内添加更多 Wi-Fi。同一 Wi-Fi 不允许重复关联相同的非空登录用户名，以免造成歧义；不填用户名的普通网络凭据可分别保存。
- Wi-Fi 名称、用户名、备注、使用时间和当前账号记录（不含密码）：`~/Library/Application Support/WiFiSwitch/accounts.json`，文件权限 `0600`。
- 密码：macOS 登录钥匙串，服务名 `org.wifiswitch.WiFiSwitch.accounts`。每个账号使用独立 UUID 索引，关联多个 Wi-Fi 仍共用这一份密码，关闭 iCloud 同步；密码不会进入 JSON 或命令行参数。
- 上述不同步限制只针对应用自己的账号条目。新增的系统默认连接同步另存系统 Wi-Fi 凭据；系统用户域可能随 macOS 的 iCloud 钥匙串设置同步。删除应用内账号只删除其独立条目，不自动删除系统 Wi-Fi 保存的凭据或忘记网络。
- 没有后台服务器、遥测或账号上传；登录凭据仅交给 macOS 进行 Wi-Fi 认证。
- 账号列表损坏时，应用停止写入并显示错误，不会以空列表覆盖原数据。
- 元数据保存失败时会恢复此前的钥匙串内容。权限拒绝、密码丢失或恢复失败会显示明确错误。

## 构建

需要支持 Swift 5.9 或更高版本的 Apple Command Line Tools（`xcode-select --install`）。测试使用工具链自带 Swift Testing，需要包含 Swift Testing 的较新工具链；应用运行不依赖测试框架。

默认采用内部使用模式，不要求 Apple Developer Program 会员。下列命令仅供从源代码打包的开发者使用，安装用户无需执行。

```sh
# 打包电脑首次准备固定本地证书；后续复用，不要每次重新生成
python3 scripts/setup-local-signing.py

# 构建应用，并将使用说明和相关文档一起打入 DMG
bash scripts/package-internal.sh
```

产物位于 `dist`。构建默认使用当前 Mac 架构，校验签名并保留上一版应用；证书缺失、签名无效或签名身份变化时会停止，不回退到临时签名。`WIFI_SWITCH_LOCAL_BUILD=1 bash scripts/build-app.sh` 可将开发测试产物隔离到 `dist/local`。

如日后需要 Developer ID，可显式设置 `WIFI_SWITCH_SIGNING_MODE=developer-id` 和 `WIFI_SWITCH_SIGNING_IDENTITY` 运行构建，并另行完成公证；它不是当前内部使用的前置条件。配置与已知限制见 [签名说明](docs/signing.md)。

## 互联网状态（0.1.51 起）

系统连接、手动连接和唤醒后自动检测，并每 30 秒刷新。检测使用 Wi-Fi 路径向 `www.apple.com` 和 `www.microsoft.com` 的 443 端口建立正常证书校验的 TLS 连接，不发送账号或密码。任一成功即通过；两者均失败再重试一轮，每次最多 4 秒。

- **绿色对钩**：已识别账号、凭据核对通过（或本次应用连接成功），且互联网探测通过。
- **黄色叹号**：互联网探测通过，但配置未知或已确认密码不同；点击添加或更新。
- **红色叉号**：断开／关闭 Wi-Fi、等待地址超过 30 秒，或互联网探测两轮均失败。悬停查看说明，网络恢复后自动更新。
- 检测中显示灰色时钟；授权失败但网络可用显示灰色信息标记，不伪称密码错误或断网。

检测通过只说明至少一个外部 TLS 端点可达，不保证每个网站、公司业务、VLAN 或实时认证身份正确。代理、VPN、门户登录或单位屏蔽检测端点可能使检测失败，即使部分网页仍可访问。此时提示“互联网检测未通过”，不会据此修改密码、DNS、自动加入设置或主动重连。主配置面板的连接通知与布局保持原样。

## 重复授权修复（0.1.53）

连接通知会合并处理，应用自身切换期间不启动竞争的凭据核对。添加／更新读取后如果发现已有账号，需要二次确认时，复用同一窗口内刚授权读取的凭据快照（最多 30 秒）；取消、关闭、连接变化或超时后丢弃，不写入磁盘。系统凭据同步去掉重复回读，仍保留一次最终回读及失败回滚。

编辑表单读取应用自己保存的密码；正常连接使用该密码。用户主动导入、更新，或连接中为保留／同步系统原有凭据而进行的必要读写，仍可能需要系统授权。此修复不保存管理员密码、不修改钥匙串权限，不能承诺所有系统操作只授权一次或永久免授权。


## 手动核对账户信息（0.1.54）

暂时读不到系统密码时显示灰色信息标记，点击打开“核对账户信息”。打开窗口不会读取密码；点击“核对”才读取系统保存的凭据，必要时由 macOS 请求授权。

- 一致：不重写密码，关闭窗口；已登记且互联网检测通过时恢复绿色对钩。
- 不一致：状态变为黄色叹号，窗口切换为“更新已保存的密码”。点击“更新”才将系统密码保存到本应用并读回验证；取消则保留黄色，不改密码。网络异常时红色优先。
- 读取失败：窗口内显示橙色错误并保持打开，菜单仍为灰色，可重试或取消。没有把读取失败当成密码不一致。

诊断记录位于 `~/Library/Logs/WiFiSwitch/credential-sync.log`：主动核对读取失败为 `verificationReadFailed`，添加／更新读取失败为 `importReadFailed`，可取得的系统错误码一并记录；不记录网络名、用户名、密码或密码摘要。定时轮询不会反复申请授权；启动和系统连接变化的自动核对见下文。


## 启动与回切自动核对（0.1.56）

已登记的 Wi-Fi 在启动和系统回切时自动比对保存的账号密码。先静默读取；无法读取且没有当前连接的一致证据时，使用与添加时相同的系统配置读取路径继续核对。系统仍认可的授权会自然复用，不要求先点灰色图标。未登记的网络仍为黄色，由用户填写描述后确认添加。

核对一致且互联网检测通过后，菜单与主面板变绿；稳定确认不同则变黄，点击后确认更新；联网异常为红色。取消、拒绝或读取失败为灰色，显示错误并可手动重试；同一连接的轮询和重复失败通知不会连续请求授权；并发的同一轮静默核对合并执行。观察到断开、其他网络、休眠或新的账号后重新获得自动核对机会。通知在 350 毫秒内合并，正在连接／导入时不竞争读取，过期结果不得覆盖新连接。

自动读取时显示“钥匙串授权说明”，列明账号名称、Wi-Fi、企业用户名，并分别说明当前读取系统 Wi-Fi 凭据还是 WiFi Switch 账号密码；添加／更新窗口也显示正在读取的目标。个人网络查询向系统 API 传递同一说明。macOS 系统对话框的标题与按钮由系统管理，尤其 CoreWLAN 授权不能自定义，应用说明窗口用于补充目标信息，不能替代授权窗口。

已有“始终允许”是否适用由 macOS 按条目及签名判断，一次系统钥匙串管理员许可不一定是永久授权。应用不保存管理员密码，不修改系统条目 ACL，不以旧密码或条目日期替代实际密码比较。此版本修复自动核对的触发范围，不宣称所有受管设备或系统钥匙串均永久免提示。

日志：`~/Library/Logs/WiFiSwitch/credential-sync.log`，新增自动核对阶段 `automaticVerificationStarted`、`automaticVerificationCompleted`、`automaticVerificationFailed`，仅记录固定阶段、结果、来源和错误码，不记录账号、网络名称或密码。

### 连接来源诊断

`~/Library/Logs/WiFiSwitch/credential-sync.log` 新增手动连接、用户确认后重连、系统抢先恢复、提交认证、连接调用返回／失败及企业连接流程完成阶段。只记录固定事件及错误码，不记录 Wi-Fi 名称、用户名、密码或摘要。日志能辅助区分执行路径，不能代替认证服务器的身份记录。用户主动断开和意外断开的来源无法从现有系统通知区分，应用使用统一的用户确认流程。
